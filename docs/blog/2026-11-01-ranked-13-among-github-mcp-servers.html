Ranked 13th among GitHub MCP servers

Glama, October 2026 · shortlisted from 2,074 GitHub servers · written 2026-11-01

What happened. Glama's 20 Best GitHub MCP Servers, Compared put MisakaNet at #13 — one of 20 shortlisted out of 2,074. The page's numbers for us: 544 GitHub stars (+34 in 30 days), last commit that day, score 51.2, and its one-line verdict — "for an AI coding agent debugging a recurring error in a code repository".

A ranking is a lagging indicator, so this page records the leading ones: what actually changed in the month that produced it, and the five mistakes that cost the most time on the way. Nothing here is a launch announcement; the numbers below are the same ones the heartbeat and the repository publish daily.

The interesting number is the third one. The triage script fetched one page of open issues and reported "12 open question(s)" — which happened to be a true statement about page one and a false one about the backlog. The other 42 questions could not receive a receipt, a cluster or a bounty, because nothing downstream could see them. Fixing that, and the digest that had quietly forked into five same-titled copies, changed what the project knows about itself more than any feature did.

Five things that went wrong

1. A one-page read reported 22% of the truth

issues?state=open&per_page=100 with no page parameter. Every derived number inherited the blind spot. Rule: a script that reads "the backlog" must page, and the paging function is written once.

2. A missing dependency was published as a fact

The heartbeat's daily comment said converted: 0 for every intake. The cause was not a pipeline failure: the workflow installed nothing, PyYAML was absent, and the provenance parser degrades to {} by design ("never raises on a malformed lesson"). So every lesson looked like it cited nothing. Rule: a failed read is never a zero — the panel now prints "could not be read (reason)" instead.

3. Three lessons were invisible because of a substring

Three readers skipped files with "TEMPLATE" in name.upper(), meant to skip lessons/TEMPLATE.md. It also skipped every lesson whose slug contains the word. The trust page said 746 lessons while the corpus said 749 — and a lesson citing intake #3418 could never satisfy its citation, so that reporter would never get a receipt. Rule: compare filenames, not substrings; and when two published numbers disagree, one of them is a bug.

4. A Windows path made a whole lesson unreadable

The batch converter emitted verify: "E:\Deepseek\...". YAML read \D as an unknown escape, the entire frontmatter became unparseable, and the gate reported every field missing — while the file looked perfect in an editor. Rule: escape both characters, and make the test round-trip a Windows path.

5. Non-ASCII filenames turned three gates red at once

git diff --name-only renders a Chinese path as an octal-escaped, quoted string unless -c core.quotepath=false is passed. Three workflows split that output on spaces and handed the tokens to a script that could not open a filename starting with a quote. Every earlier lesson had an ASCII file stem, so the bug had been there for months. Rule: the flag goes on every changed-file listing, and a test reads the workflows to keep it there.

The part that does not fit in a changelog

Two things happened this month that a milestone list cannot carry. The first: an outside security audit of the repository found a real defect — a one-time pairing code that could be redeemed twice under concurrency, issuing two working tokens. It was small, it was found by running this repository's own code against itself, and it took four lines to fix once it was stated plainly. Twenty findings were reported; three were real and are fixed, one was disproved by the auditor's own experiments, and the rest are notes for a roadmap.

The second: the release sat open for six days. The pull request was green, the changelog was written, and nothing merged it — because release PRs here are deliberately excluded from auto-merge (a release in September shipped 30 duplicated changelog entries that way). The lesson is not "automate the merge"; it is that an artifact kept for a human to read needs a channel that tells the human it is waiting. The repository has a heartbeat for everything except that.

Open source at this size is mostly bookkeeping. The corpus grew by 233 lessons, and each one needed its provenance checked, its title repaired, its domain mapped, and a receipt written to whoever reported it — often a stranger who will never read the reply. The代码 is the easy half.
