## 3. 可复用的判据

1. **发布链路要端到端跑一次才算存在。** 这轮三个"应该能发"的东西全部在第一次真跑时坏：
   release-please 只给根包打 tag（npm 永远收不到）、`git tag -a` 在 runner 上没有身份、
   包的 `files` 漏了 `src/lib/spawn-command.js`（两个版本都装不上）。每一个都是"看起来发布成功"。
2. **`files` 与 require 图会漂。** 判据不是"检查了几次"，而是**打包产物能不能跑**：
   `npm pack` → 解包 → 运行入口。已经写成门禁（`tests/packaging.test.js`）。
3. **答案键要读 base，作者断言要读工作区。** 课程门禁的词表两个半边来源不同：`corpus` 读 base
   （否则 PR 把自己的词写进答案键），`allowlist` 读工作树（否则作者在同一 PR 里加的允许项永远看不见）。
   这轮第一次从 intake 转课程时就被它挡住。
4. **生成式回填的瓶颈是判断力，不是生成量。** 20 条候选里 10 条要被丢掉，且理由稳定（编造机制、
   verify 分不出修没修好、与正文冲突、超长/语言混杂）。把这些理由记下来，下一轮才有可比性。
5. **加一节课程 = 改一串生成物。** 顺序固定：`rebuild_lessons_index` → `update_lessons_json` →
   `build_lesson_pages` → `gen_ranking_snapshot` → `export_okf` → `evidence_distribution`
   （**表要手工贴**）→ `export_public_vocabulary`（**最后**，因为它的 corpus 含 `path`）。
   `check_dist_diff.py` 会红两次：一次是没重建，一次是重建了没提交 —— 两个都要走一遍。
6. **并发 agent 要用独立 worktree。** 本轮 mcode 与主会话共用一个工作区，一次 checkout 把未提交的
   改动带到了别人的分支；mcode 自己发现并修复（移提交、复位分支、搬 worktree）。规则写下来：multiplexed
   agents 一律 `git worktree add`。
