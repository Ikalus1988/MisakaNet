## 4. 增长分析

**漏斗**：发现 → 分发 → 接入/激活 → 复用 → 贡献回馈。

**五个泄漏点（每条都有证据）**

1. **激活不可测**：funnel 四指标零埋点（见 P0#3）。
2. **最容易拿走的是引擎，不是能力**：`misakanet-core` 8,774/月 vs 安装器 501/月。产品承诺是"你的 agent 会主动查"，
   而多数下载走的是"把检索库拿走自己集成"——中间那条断层没有任何人测过。
3. **分发面自己在漂**：npm 落后一版；对外说 393 而 D1 有 405。
4. **审核队列是人因瓶颈**：11 条挂着；外部合并占比 8/100。
5. **需求信号没闭环**：83 个未命中家族（"monolithic frontend / 909-line app.js" 这类**通用软件工程重构**需求）
   没有对应的"下周该写什么"排期动作。注意它同时说明：**未命中主要是语料缺口，不是检索能力**。

## 5. 仓库短板（工程）

1. **bus factor 1**：95/100 合并来自一人；历史 CI 积压 1,804 条 held runs。
2. **免费档 KV 额度常年不够**：12 天里 9 天超（#1890），今天 06:43 UTC 又打满；根因是"按实体建键"的写入形状。
3. **可观测性欠账**：health 曾 40% 概率骗人；KV 错误分类器两次被生产纠正（`[code: 10048]` → 再到
   `KV put() limit exceeded for the day.` 这种无码措辞）；funnel 零埋点。
4. **"同一事实多个面"反复出现**（已修 3 起）；仓库**没有 link checker，也没有 markdown lint**。
5. **测试结构缺口**：3 个 MCP 模块在本地因 `mcp` 版本无法收集（CI 用 pin 版本）；历史上 `audit` 的
   pytest 步骤 `continue-on-error` 会掩盖失败。
6. **i18n / 文档一致性靠人工**：i18n 一致性测试尚不存在（#1894）；`setup_docs` 测试只覆盖 4 个入口。

## 6. 用户与产品维度

| 层 | 是谁 | 证据 | 现状 |
|---|---|---|---|
| **A 使用方 agent（主用户）** | Claude Code / Codex / Cursor… | MCP 匿名读、19 条 agent intake | 读不限次（2026-09-18 起）——最好的待遇给了主用户 ✅ |
| **B 集成方开发者** | 自己写代码要检索 | `misakanet-core` 8,774/月 | 有库有文档，但没有"接入后是否生效"的验证路径 |
| **C 贡献者** | zsxh1990、laurentketterle-hub、2lll5… | 提交/PR 真实存在 | **回应周期不可预期** ⚠️ |
| **D 人类访客 / 评审** | stars 493、UV ~176 | GitHub API | 能看，但没有复访理由 |

**产品缺口**

- **没有"我"**：无登录、节点是化名（刻意的隐私设计）→ 无法做留存/复访，也没有组织/团队面。
- **没有状态与承诺面**：`/api/health` 刚修好，但没有公开状态页；对"agent 依赖的基础设施"缺少 SLA 表述。
- **只有 pull，没有 push**：价值依赖 agent 在正确时刻主动调用；没有 IDE 插件、CI 集成或主动提示。
- **激活路径未闭环**：安装器写了配置，但没有回执证明它生效（`--report` 是手动的）。
- **定位张力**："zero bounty + maximum rigor"是好的贡献筛选器，但对留存是负向的：没有金钱、署名机制弱、审核慢。

激活完全不可测"这三件才直接作用于漏斗。它的"命中率是杠杆"方向对，但因果要分清：**0.234 → 0.466 是注入课程
带来的提升，未命中集中在 gap 家族的通用重构需求上，所以是补语料，不是改检索**；而它建议的 #1527 那块已经交付。
