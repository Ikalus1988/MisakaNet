### 86.1 `README.zh-CN.md` 只有 4 块徽章，而日文版是 19 块

起因是一句「中文 readme 徽章缺失」。实测清点三个 README 的**全部链接徽章**（此前只看
shields.io 会漏掉 Glama / MCP Toplist，结论会偏小）：

| 文件 | 徽章数 |
|---|---|
| `README.md` | 19 |
| `README.ja.md` | 19（href 集合与顺序逐一对齐） |
| `README.zh-CN.md` | **4** |

日文版 19/19 说明**徽章对齐是既定设计**，中文版才是漂移的那个——不是「翻译版只保留少数」。
缺的是 CI、MCP 工具数、检索后端、Python/PyPI/npm，以及全部 9 块生态徽章。

代价不是不美观。`README.zh-CN.md:102` 写着「当前发布到 npm 的版本见**本页上方的 npm 徽章**」，
而整页 npm 徽章实测计数为 **0**——这句话把读者指向文档某个区域，让他在那里找一个不存在
的东西。与 §82 修的 `docs/reputation.md` 指向 404 端点是同一类缺陷。

**为什么没有任何门禁发现它**（这一条比徽章本身更值得记）：

- `sync_lesson_count.py` 负责的是 lessons 徽章**内部那个数字**，不负责徽章在不在；
- `tests/test_lesson_count_ssot.py` 管哪些页面**可以引用**计数，不问某个翻译版是否还带着徽章；
- `tests/test_readme_asset_budget.py` 只扫 markdown 的图片语法（`!` + 方括号 + 圆括号），
  而 shields.io 徽章是 `<a>` 包着的 HTML `<img>`，对它完全不可见。

  （这一条是我自己撞出来的：第一版这里直接写了那串 markdown 图片语法作为示例，而
  `test_integration_docs_truth.py` 的链接正则是裸跑全文的、不跳过行内代码，于是把它当成
  真链接去解析，CI 七个平台一致红。**在 markdown 文件里书写 markdown 语法，会被 markdown
  门禁当成真链接**——该门禁只对围栏代码块做了豁免，行内代码没有。）

三条都「看起来覆盖了徽章」，合起来却让「一个 README 缺 15/19」的状态**全绿**。
`sync_lesson_count.py` 的文档字符串早就写过这个形状——`gemini-cli.md` 的无徽章计数与
`README.zh-CN.md` 的退役 node 徽章——但那次的结论是「去掉计数」，不是「徽章集合会漂」。

已修（#3154 / `e580f569`）：按 `README.md` 的三块结构补齐，新增
`tests/test_readme_badge_parity.py`。判据运行时从 `README.md` 读、不硬编码 19；`alt` 文本
不参与比较（`知识` 与 `Lessons` 是正确翻译）。**变异测试双向命中**：删 zh-CN 的 CI 徽章、
删 ja 的 Benchmark 徽章各自转红，恢复后逐字节一致。
