**可复用判据**：`probeLessonsRead` 打的是真实的 `LIMIT 1` 单行查询，不是缓存也不是推断，所以
`error_kind=quota` 是**此刻**被 D1 拒绝。于是"等零点"只在"耗尽的额度确实是零点重置的"前提下成立；
零点后 14 小时仍拒绝，只剩两种解释——**(a) 日窗口不是 00:00 UTC**，或 **(b) 额度在每天零点后数小时内又被烧光**。
区分这两者要读 CF 账户分析，也就是 §103.6 第 2 条缺的那个 token。

## 105. 顺手的发现：`deploy-freshness` 在"一切正常"时也会红

`check_deploy_freshness` 比的是 `commit_sha` 与 HEAD **完全相等**；而 `deploy-worker.yml` 只在
`workers/register-proxy-sw.js`、`workers/wrangler.toml` 变动时触发。两者一乘，结论是：
**任何一次 docs-only 落地都会把它弄红**，直到下一次 worker 改动。

实测（2026-10-18，部署成功之后）：

- 生产 `6699a3b5`，HEAD `fb95ea17`，相差 2 个提交——`a0bb02aa`（Quickstart 复制按钮）、`fb95ea17`（handoff），**都不碰 worker 路径**；
- `git log 6699a3b5..HEAD -- workers/register-proxy-sw.js workers/wrangler.toml` **为空** → 生产跑的正是最新的 worker 代码；
- 可 `python3 scripts/doctor.py --deploy-freshness` 仍然 ❌：`production runs 6699a3b5…, but this checkout is fb95ea17… — 2 commit(s) behind. The worker is stale; the deploy did not land. (#2779)`

`deploy-freshness.yml` 的 run 历史是同一个形状：部署完成那一刻 success，下一条 docs 提交之后 failure。

**候选修法（未做，留给下一轮决定）**：把比较基准从 HEAD 换成"HEAD 上最后一次触及 worker 触发路径的提交"
（`git log -1 --format=%H -- workers/register-proxy-sw.js workers/wrangler.toml`），并在
`tests/test_deploy_freshness.py` 里补一条"docs-only 提交不算落后"的用例。
门禁该抓的是**部署没落地**，不是**文档又写了一段**——#2779 的历史教训不能被换成另一种误报。
