## 3. 新发现 1：GitHub Pages 的 legacy Jekyll 构建自 #1793 起每次都红

- **起点**：`9131c5443`（PR #1793，09-17 01:07）之前全是 `success`，之后每次 push 都是 `failure`
  （workflow 名 `pages build and deployment`，job 里的 step `Build with Jekyll`）。
- **根因**：`docs/maintainer/enterprise-deployment.md:317` 的 Ansible/Jinja 表达式里有一个 `'{}'`。
  Liquid 4.0.4 的分词器是 `VariableIncompleteEnd = /\}\}?/` —— 它在**第一个** `}` 处结束变量标签，
  于是 token 变成 `{ { ((mn_report.stdout or '{}'`，`ContentOfVariable`（要求结尾是 `}}`）不匹配 →
  `raise_missing_variable_terminator` → 整个 Pages 构建失败。
  （`{ {` 不是笔误：把那一行**原样**贴进 `docs/` 就会重复它正在描述的故障——写这份 handoff 时我先
  原样写了，扫描器立刻在同一位置报了同一个致命 token。）
- **复现**：按 `lib/liquid.rb` + `lib/liquid/block_body.rb` 的两条正则写了一版忠实移植的扫描，
  在 `docs/` 的 **692 个文件**里只有这 **1 个**致命 token，行号与生产报错逐字一致。
- **关键判断：把文档改成"Liquid 安全"是错的修法。** 线上站点 100% 是 mkdocs
  （`/glossary/` 200 且 `generator=mkdocs-1.6.1`；`/glossary.html` 404；primer 主题的
  `/assets/css/style.css` 404），由 `docs.yml` 的 `deploy-pages` 发布。而 legacy 分支构建**也**往同一个
  Pages 站点部署（deployments 里有 `github-pages[bot]` 的记录）——即**两个发布者抢同一个站点**，
  站点长相取决于谁最后部署。让 Jekyll 构建重新成功，等于把发布权交回给它。
- **处置（已做）**：把 Pages 的 `build_type` 从 `legacy` 改成 `workflow`
  （`PUT /repos/Ikalus1988/MisakaNet/pages`，204；再次 GET 确认 `build_type: workflow`）。
  legacy 构建不再运行 → 这个常红检查消失，mkdocs 成为唯一发布者。**合并后第一次 push 时请确认**（§6）。

## 4. 新发现 2：`lessons/TEMPLATE.md` 的 frontmatter 从 2026-06-23 起就是坏的

**09-16 handoff §4 与 §7 的前提因此不成立**：它说 #1746–#1750"内容好、只缺 DCO 签核"。不是。

- **症状（误导性）**：门禁报 `missing required field: title`（还有 `domain`/`tags`/`status`/`evidence_level`）

- **机制**：模板的 frontmatter 是"4 行 YAML + 一行 legacy JSON"。在 YAML 里那行 JSON 是一个
  **没有值的复杂键**，`yaml.safe_load` 直接 `ScannerError: could not find expected ':'`；
  而 `lesson_gate.parse_frontmatter` 用 `except Exception: pass` 把解析错误吞掉、返回 `{}` →
  于是"解析失败"被报成"字段缺失"。**这个吞掉错误的 `pass` 是误诊的真正来源。**
- **时间线**：2026-06-14 `c8c7782bf` 建模板时是 JSON frontmatter；2026-06-23 `ea29db230`（#250，
  "standardize lesson metadata headers"）把 YAML 键**加在那行 JSON 上面**而没有替换它 → 从此不可解析。
- **为什么三个月没人发现**：`scripts/fix_frontmatter.py`（2026-08-28 专为**同一类**损坏写的：
  "Broken `'{"title"':` JSON-injection lines inside YAML frontmatter"）扫的是 `canonical_lessons()`，
  **它排除 TEMPLATE.md**；而 `lesson_gate` 只在 PR 改动的文件上跑，没人改模板就一直没人看它。
  语料被修干净了，**模板被留在了病中**。
- **后果**：#1746–#1750 五个 fork PR 逐字照抄模板（`verification: "metadata-normalized"` + 那行 JSON
  是模板的指纹），所以五篇**都在 `gate` 上结构性失败**，只修 DCO 一样是红的；它们还都用自造域名
  （`llm-integration` / `llm-observability` / `data-pipeline` / `narrative-consistency` / `roleplay-safety`，
  都不在 `data/domains.json` 的 46 个里）——这是修完 frontmatter 之后会撞的第二面墙。
- **已做**：五个 PR 各一条评论，写清三件事（合成一个合法块、域名取词表、`evidence_level` +
  三个结构化字段），并给了**在该 PR 的文件上实跑过门禁**的完整 frontmatter（`gate` exit 0、
  `provenance` exit 0）。
- **语料本身是干净的**：440 个 tracked 课程文件，**0** 个 frontmatter 不可解析。只有模板 + 那五个 PR。
- **修**：**#1796**（lessons-only）：块改成单个合法 YAML，带齐新课程需要的全部字段（含 #1783 的三个
  结构化字段）；模板规则表里"JSON inside `---`"与"required fields 只列 title/domain/status"两行同样是错的，
  一并改正。改前 `--existing` 6 findings → 改后 **0**；同一正文换新旧两种块是 exit 1 → exit 0。

## 5. 新发现 3：`auto-merge-lesson` 一个也合不了（已修 #1797）

- **首次真实运行**：给 #1796 打上 `auto-merge-lesson`，run **35204235065**。日志：

  ```
  verdict (exit 0): merge: lessons-only diff (1 file(s)), all required checks green,
                    label 'auto-merge-lesson' present, not a draft, no changes requested
  ##[warning]PR #1796 is no longer a clean candidate
             (mergeable=true state=open draft=false label=true) — leaving it to a human.
  ```

  判定说 merge，合并前复核紧接着说"不再合格"。
- **根因**：复核读的是 `GET /repos/{owner}/{repo}/pulls/{n}`，REST 的 `mergeable` 是**布尔**
  （`true` / `false` / 计算中是 `null`），代码却拿它跟 **GraphQL** 的枚举串 `MERGEABLE` 比。
  `true != MERGEABLE` 恒真 → 每个候选都走"leave it to a human" → **通道永远合不了任何东西**。
- **为什么测试没抓到**：`tests/test_lesson_pr_mergeable.py` 覆盖的是 python 判定；这段 shell 复核没有
  任何测试；桩回放喂的是**作者心里的形状**（枚举串），不是端点返回的形状。教训与 09-16 §6.2
  （"桩回放查不出权限类错误"）同源：**桩能验证逻辑，验证不了契约**。
- **修**：`mergeable_is_clean()` 归一化两种形状（`True`/`"MERGEABLE"` → clean；`None`/`"null"`/
  `False`/其它 → unclean），工作流里的内嵌脚本打印归一化结果、shell 只比较 `clean`；新增单测钉住两种
  形状，并断言"shell 不得再拿原始拼写比较"；`docs/maintainer/auto-merge-lessons.md` 里那句
  `mergeable == MERGEABLE` 就是错误源头，已改，并在风险表里补了这一行。
