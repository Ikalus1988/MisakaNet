## 1. 这一轮定下来的判断

1. **身份用两种方法，显示层只有一个名字**。`contributions` 增加 `login`（`gh:<login>` 伪名 +
   handle 同存），面板在有 handle 时显示 `GH` 徽章与 handle，否则显示伪名。**GitHub 的一半是
   可验证的**：来自合并的 lesson PR 的 `user.login`（`lesson-authors.yml` 每日巡检），不是提交者自报。
2. **`used`（被取用）的权威来源是 `lesson_authors`**：路径 → 作者（只认 `status="added"` 的文件，
   改课不算作者）。端点在 ops 库把 `search_signals.top_id` 与它 join，按 0.2/次计分。
3. **`top_id` 有三种形态**（实测 16k 条）：课程 id、文件路径、纯文件名。join 必须三种都接受——
   只按路径 join 会让 `used` 恒为 0，那是**假为零**，不是"没人取用"。
4. **面板层次靠分隔线，不靠句子**：`SECTION_TITLE`（16px 间距 + 1px 线 + 11px 大写标签）；
   语料榜 ⑥⑦ 折进 `Network & corpus`；activity 并进计数条；voice 一行开关；空状态一句话。
5. **本地数据三个键**：`misakanet.panel.stats.v1`（计数）、`history.v1`（最近 20 次检索）、
   `node.v1`（认领的伪名）。都是公开/可再生的，不含 token。

## 5. 坑（都是这轮踩过的）

- **npm staged vs live**：`npm publish` 打印 `+ pkg@3.15.0` 不代表已上线。
  查 `https://registry.npmjs.org/<pkg>/<version>`（版本端点新鲜），不要查全量文档（CDN 会缓存）。
- **admin merge**：仓库规则在“有检查 in progress”时连 admin 也拒；要么等，要么先让检查跑完。
- **disposable host 的插件缓存**：按 package 版本缓存 client bundle。改了 `lib/client.js` 但版本没变
  时，页面还是旧的；bump `package.json` 版本或重启 host。
- **时间格式**：`contributions.created_at` 是 sqlite 的 `YYYY-MM-DD HH:MM:SS`；API 绑 `since` 必须
  同格式，否则边界那天的行会被静默排除（已修，`sinceSql`）。
- **e2e `settings-to-panel`**：断言面板文本 `Voice: off`；改 voice 文案会连带它失败（不是 flake）。
- **回填的工作量**：每个 PR 2–4 次 `wrangler d1 execute`，100+ PR 会超过 15 分钟；分批或加超时。
