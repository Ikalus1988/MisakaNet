## 1. 判断

### 1.1 「全表扫」不该逐条修：三层，各有各的盲区

同一类缺陷在这个仓修过两次（2026-10-21 每次扫 68,892 行；2026-11-24 每次读 1,040 万行）。第一次的收尾是
`tests/test_d1_read_hotspots.py` —— **为那条查询手写的** replica 测试；它没覆盖第二次，而 worker 里有
**70 个 `prepare(` 站点**，这个模式永远只覆盖"被想起来的那几条"。

所以机制按**覆盖面**分层，而不是按"有没有门"：

| 层 | 覆盖 | 盲区 |
|---|---|---|
| **L2 形状门**（`tests/test_worker_join_is_indexable.py`） | 任何 `JOIN … ON … OR …`，与版本无关、PR 阶段就红 | 只抓形状；"在没索引的列上 join 但没有 OR"漏 |
| **L1 运行时计量**（`workers/lib/d1-cost.js`，包在 `d1Binding()`/`opsD1()`） | 每条语句的 `D1Meta.rows_read`，70 个站点一个都不用改 | `first()`/`raw()` 不返回 `meta`；新 isolate 从零开始 |
| **L3 每日体检**（`scripts/d1_cost_report.py` + `d1-cost.yml`） | 账户级、按语句、**次日**出结果，且报"新出现的语句" | 滞后一天；需要 `CF_ANALYTICS_TOKEN` |

**判据**：问"这条判据覆盖哪一类失败"，不要问"有没有门"。三层里没有一层单独够用，但每一层的盲区都被
另一层覆盖。

### 1.2 计划断言不能当通用门

同一条改写后的 SQL，**本机 SQLite 与 CI 的 SQLite 给出两种不同计划**（一个从 `search_signals` 驱动、
一个从 `lesson_authors`），两者都线性。所以 `EXPLAIN QUERY PLAN` 的门会随版本翻红；**形状**才是可移植的判据
（`ON … OR …` 在任何 SQLite 上都是二次的）。证明某条具体查询的计划，留在那条查询自己的 replica 测试里。

### 1.3 「读放大」的读数必须按语句拆

账户级日读量从 2.98B 掉到 181M 是同一条语句的功劳；只看账户总量只会看到"今天少了 94%"，不知道是谁。
**判据**：任何"读太多"的判断先按 query 分组（`d1QueriesAdaptiveGroups` 自带 `query` 维度，不需要
`wrangler d1 insights`），再看 **rows/call** —— 一个总量分不出"形状坏"和"很忙"：5,000 次便宜调用和
1 次灾难调用落在同一个数上。

### 1.4 「线上落后 main」≠「worker 落后」

`deploy-worker.yml` 只在 `workers/**` 变更时触发。这一卷收工时线上是 `693d171e`、main 是 `957ab2bf`，
但中间 7 个提交**没有一个**碰 `workers/`，所以生产跑的就是最新 worker 代码。

**判据**：`git diff <live_sha>..main -- workers/` 为空就不是漂移。`deploy-freshness` 现在只比 SHA 相等，
它会把"main 上了七篇文档"报成"线上落后" —— 这是它下一步该改的口径（不是 bug，是精度）。

### 1.5 归因链的第二次修正（承 vol 45）

安装量总量跟发布节奏走（发布次日 2.2× 基线）；剔掉发布日与次日，npm 基线 **≈132/天**、PyPI **≈27/天**，
21 天窗口 +3%，是**平**的而不是衰减。这一卷没有推翻它，只是把"平"落到"激活"这一格仍然没有读数。

## 5. 坑（本卷实际踩到的）

1. **workflow 里声明的 env，必须在**该步的 shell 文本**里出现过** —— 只在 `scripts/*.py` 里读不算。
   `tests/test_workflow_env_is_used.py` 会在八条 test 腿上同时红。
2. **`node:sqlite` 的计划跨版本不同**，所以断言"用了哪个索引"的测试会翻红；断言**形状**（无 `CROSS JOIN`、
   每分支至多一次全扫 + 至少一次索引查找）。
3. **本仓的 heredoc 会吃掉 `\n`**（本轮踩了三次）：在 bash heredoc 里写 Python 生成 JS 时，
   `"\\n"` 到文件里可能变成真换行。用 `edit` 工具改，或 `chr(10)`。
4. **GitHub 的 `mergeable` 在 push 后短时间内是 `UNKNOWN`**，不是"没冲突"；任何自动化都必须把它当
   "读不到"（exit 2），否则会把冲突读成可合。
5. **`cfut_`（OAuth access token）打不了 `api.cloudflare.com/client/v4`**（header 格式被拒），
   GraphQL 分析只认 API token；且该域从本机偶发 `SSL: UNEXPECTED_EOF_WHILE_READING`，同一时刻 `curl` 是 200
   —— 所以报告脚本要重试，不要"一次失败就当天没数"。
