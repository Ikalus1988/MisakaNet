## 3. 本轮踩的坑（已修，且多数已固化进流程）

1. **npm 不认单独的 `NODE_AUTH_TOKEN`**：必须 `.npmrc` 里写
   `//registry.npmjs.org/:_authToken=${NPM_TOKEN}` 由 npm 运行时插值（CI 里是 `setup-node` 自动写的）。
   本机发布因此先撞了一次 `ENEEDAUTH`。
2. **npm 用 `PUT ... 404` 表达"这个令牌无权创建新包"**，而 **401 才是令牌失效** —— 两者混在一起时
   完全无法定位；现在工作流会打印账号与令牌可达范围，并明确"401 = 过期，不是权限"。
3. **`(?m)` 是 Python 正则语法**，JS 必须把它作为 flag 传给 `new RegExp(re, 'm')`（4 处运行时直接抛 `Invalid group`）。
4. **JS 不拼接相邻字符串字面量**（Python 会）→ 首轮自报文案只剩前 1/3，靠测试才发现。
5. **整段替换式重构会误删函数**：删掉了 `failureText`/`_failure_command`，8 个钩子测试当场变红。
6. **CodeQL 的 `file-access-to-http` 判定的是"文件数据是否流入外发请求"，不是"发往哪里"** ——
   所以正解是**删掉那个不必要的流向**（钩子不再读 token 文件、`--verify` 不再带凭据），而不是加压制注释。
7. 本机跑 npm **必须把 cache/logs 指到 /tmp**（`$HOME` 只读），并注意空 `userconfig` 会让 `npm install` 失败。

## 5. 教训（一句话版）

- **按用户的真实入口验证**：`npx` 在干净缓存里跑一次，才算"用户能用"；按我们自己的调用方式跑通不算。
- **失败信息必须自解释**：`PUT 404` 与 `ENEEDAUTH` 各花掉十几分钟，现在都写进了工作流输出。
- **涉及凭据的代码，删流向优于加压制**：压制会让下一个人以为风险已被处理。
