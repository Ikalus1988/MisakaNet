### 122.3 五个顺带查出来的真 bug（都是同一种病：两个作者各写一份）

1. **证据徽章色阶整体错位一档**。`docs/evidence-badges.md` 的契约是 E0 灰 / E1 红 /
   E2 橙 / E3 蓝 / E4 绿，`docs/assets/badges/evidence-e*.svg` 的画面也是这五个颜色；
   而搜索页的 CSS 是 E1 **蓝** / E2 **绿** / E3 **橙** / E4 **紫**。读者看到的颜色
   和徽章本身的颜色不是一回事。现在芯片用 artwork 的颜色，契约和画面对上了。
2. **贡献等级色阶写了两份**。首页的 `.contrib-badge-*` 与脚本里填 XP 进度条的 `fillColor`
   各写一套："bronze" 一个是天空蓝一个是铜色，"silver" 一个是品红一个是银灰。
   现在两边都是金属色阶。
3. **死 CSS**。journey 页的 `.ring-1/2/3` 三条规则没有任何元素能命中（那段环图是步骤点画的），
   而其中一条还是站点最后一个紫。删掉，不是改色。
4. **抽屉里的品牌字是第三种写法**（"MISAKA NET"）。
5. **门禁自己有半只眼睛**（详见 §122.4）：`colour_hsv()` 解析不了带 alpha 的 `rgba()`，
   基线上 14 个手写页里 **250 处** `rgba(·,·,·,·)` 门禁一个都读不出来，其中 **25 处**
   本该被抓住（16 处旧 GitHub 蓝、7 处紫、2 处分类色阶），而 12b 报的是"0 处"。
   前四个 bug 是页面写错了，这个是**门禁看不见**——比前四个更坏：前四个至少有人看得见。

### 122.4 门禁：紫色从"七个 hex 的名单"改成按色相判定，还挖出了门禁自己的一个洞

原来判据 12b 靠一份手写的 hex 名单（`#a371f7` ×6、`#7c3aed` ×1）。**那份名单漏了
`#bc8cff` 和 `#d2a8ff`**——报告说"0 处"的时候，页面上还有三个紫。按色相重数，
基线上的紫是 **18 处 / 5 个页面**，不是名单里的 7 处：

| 色值 | 处数 | 页面 |
|---|---|---|
| `#a371f7` | 6 | search、start |
| `rgba(163,113,247,·)` | 5 | search、start |
| `#d2a8ff` | 3 | journey、search |
| `rgba(210,168,255,·)` | 2 | journey |
| `#7c3aed` | 1 | index |
| `#bc8cff` | 1 | pr-genius |

现在的判据：

- **主色带**：色相 195°–290°、饱和度 ≥ 0.45、明度 ≥ 0.5。三个条件都要：页面里全是
  蓝相的近灰（`#8b949e`、`#c9d1d9`、`#30363d`）和深色面（`#0f172a`、`#1f3a5f`），
  只看色相会把它们全扫进来，报出一个浏览器里根本不存在的站点。
- **紫色带**（250°–290°）：**自己的**饱和度地板 **0.30**，比主色带低。为什么低：
  `#d2a8ff` 的饱和度是 0.34，用主色带的地板它就从门禁眼皮底下走过去了——而它就在
  当初"名单漏掉"的两个色值里。淡紫还是紫。地板取 0.30 是量出来的：全站 588 个页面
  （14 个手写页 + 571 个产物页）里没有一种颜色落在 250°–290° 且饱和度 ≥ 0.30。
- 白名单 **5 条**，每条带理由（理由是数据，不是注释）：证据徽章的 E3 蓝（契约规定）、
  journey 终端模拟的 audit 行（模拟的是工具自己的输出，七种行类型）、搜索页结果徽章的
  setup 色（六级分类色阶），外加**首页英雄区的两层环境辉光**——那是 owner 明确说过
  不动的辉光，实测最紫的一个像素是 `rgb(16,18,40)`，是暗海军蓝的雾，不是第二主色。
- 新增判据 15（页脚壳）与 16（页脚壳由共享 token 块拥有——块里删掉这条规则，
  `sync_design_tokens.py --check` 仍然是绿的，因为页面和块仍然"一致"，只是一致在什么都没有）。

**门禁自己的洞（本批查出来的第五个 bug）**：`colour_hsv()` 用 `fullmatch` 去匹配
`rgba?\(...)` 的**三段前缀**，所以**每一个带 alpha 的 `rgba()` 都不解析**——包括
`rgba(88,166,255,0.12)` 和 `rgba(163,113,247,0.14)`。门禁看不见的颜色，就是门禁管不住
的颜色：基线上 14 个手写页里 **250 处**带 alpha 的颜色对判据 1 和判据 12b 完全隐形，
其中 **25 处**是真正的违规（16 处旧 GitHub 蓝、7 处紫、2 处分类色阶）被静悄悄地放过，
而判据 12b 报的是"0 处"。

修法是拆出 `colour_rgb()` 统一解析，`alpha` 可选；顺带把白名单的键从**字面量**改成
**颜色身份**（`(rel, (r, g, b))`）——`#3b82f6` 和 `rgba(59,130,246,0.14)` 是同一个颜色，
按字面量记的白名单会放过 hex、静悄悄地禁掉 rgba，E3 徽章自己的底色就是这么被报出来的。

修完之后门禁在基线树上报 **143 处**：18 处紫、89 处第二主色、36 处底色/页脚。
（改之前是 138 处：紫色带的地板降低之后，`#d2a8ff` 那 5 处也浮出来了。）

`tests/test_site_design_convergence.py` 25 → **46 条**。

### 122.5 像素对比与测试
