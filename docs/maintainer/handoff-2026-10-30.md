## 3. 可复用的判据

1. **`TTFB` 与 `total` 分开量**，才能说清是 worker 还是路径：大 total 小正文 = 路径；TLS 完成后的长 TTFB = worker。
2. **机器上有代理时 `time_connect` 量的是代理**（本例 `127.0.0.1:7890`）。先看 env，再解释 connect。
3. **"三份拷贝一致"要比较模式文本，不只是替换串。** 卡号规则能漂移，正是因为门禁只比了后者。
4. **第二台机器必须和尖峰同时。** 不同时的对照只能说明"那时不慢"。
5. **卡号是形状不是位数**：13–19 连写、4-4-4-4（及 4-4-4-4-1..3）、4-6-5、4-6-4。
6. **词表测试钉住的负例是真门禁。** `assert "mico" not in tokens` 抓到的是投稿课程里的内部平台名与内网域——脱敏不只管凭据，也管内网标识。
7. **生成物冲突的解法是固定顺序**：merge `main` → 冲突文件一律取 `main` 的版本 → 重跑索引/`lessons.json`/页面/排名快照/OKF/证据表/词表 → 提交。手改生成物会过不了"生成器是 no-op"那条测试。
8. **"命中率 15/20" 与 "哪几条差一名" 是两个读数。** 报告只列掉出前三的行时，第二名的行在任何一次运行里都不存在——那正是这 4–5 条一直没人看的原因。
9. **维护者代推外部 PR 时 `git push origin` 推到的是 upstream 同名分支**，不是 author 的 fork；推到 fork 要显式加 remote（本轮踩过一次，同名分支已删）。
10. **加一个客户端到 `AGENTS` 是"八处一起改"。** `#4083` 一次点红六个文件里的八条断言：客户端表、README 的 Installer-managed 行、Quickstart（两种语言 + 页面 fallback）、注册选择器 + 两个词条、包 README 的名单。它们不是噪音，而是"清单在哪些面上对外承诺"的完整列表——逐条改完再谈"加个目标"。
11. **手写的数字挨着生成块，会像生成块本来不会漂那样漂。** `/install/` 的 "Show the ten supported clients" 压在十一行表上。修法是把数字也交给生成器（`render_summary`），不是改这个数字。
12. **用户导出的设置不能越过 `--home <沙盒>`。** `DSH_HOME` 让安装器自己的测试写掉了真实的 `~/.dsh/AGENTS.md`（截成 35 字节）。判据：`--home` 是"把这个目录当家"，所有派生路径都必须落在其下。
13. **`--verify` 的"完整"必须覆盖新目标。** 新目标不进检查表时，删掉它的文件仍报"安装完整性：完整"——接入一个新客户端的最后一条清单应该是"它进不进 verify"，而不是"它写不写文件"。
14. **发布链路的三段要分开看**：tag 有没有被建、workflow 有没有被 dispatch、npm 上到底有没有那个版本。0.8.1 前两段都有、最后一段靠人补；0.9.0 三段自动，但 `release` environment 的**批准**仍是设计里的人工闸门——它是给人看的，不是漂移。
15. **"谁决定排序"和"谁判断相关性"必须是两个变量。** 二者共用一个 `decidesOrder` 时，把 CJK 的排序改成按展开词，就同时把别名喂进了相关性地板，#2358 那条"自信的错误答案"当场回归（`chrome-relay` 又出现在 `wsl2 landlock 文件系统沙箱` 里）——门禁在同一个 run 里抓住了。改一个看似只影响排序的开关，要问它还被谁读。
16. **修期望不能抬 floor。** 把可接受集合补全（residual 5 行）确实让 hit@1 变漂亮，但那不是搜索变好；floor 只按**代码**改动抬（CJK top-3 16→18，floor 15→18），多出来的两行当余量。
