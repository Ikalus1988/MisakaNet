## 2. 跨卷悬账

### 2.1 `#4052`：测量做完了，结论是"两个不同的停顿"

- **不是重建**：28 次读数 `builtAt` 恒为 `09:16:00Z`、`lastRefresh` 恒为 `fresh`，每次搜索都是 `worker-bm25`。
- **暖 isolate 上索引读不慢**：`/api/search-index`（本质只有一次 `readStoredIndex`）走代理 p50 1.29 s / max 1.80 s。
- **两种停顿**：A) 客户端路径——TTFB 小、total 大（11.8 KB 正文走 6–27 s）；B) 冷起点——runner 新 job 首个请求 TTFB 25.9 s（TLS 0.18 s 之后又等 25.7 s），随后 29 个请求 0.21–2.56 s。
- **并发对照**（同 5 分钟）：本机直连 p50 8.95 s / max 61.6 s；runner p50 0.63 s。第一次 runner 窗口与尖峰**不重叠**，不能用来下结论。
- **下一步**：冷路径（`loadLessons` 全量 D1 读 + `readStoredIndex` 的约 500 KB 行）只能靠日志插桩分离，**需要一次部署**；客户端 curl 已量到头。结论已贴 `#4052`。
- **追加读数（2026-10-30 晚，0.9.0 + `206224ff` 部署后）**：它不只是慢，是**会失败**。同一分钟内连续发搜索：`/api/health` 与 MCP `initialize` **16/16 全部 200**，而 `misakanet_search` 有 1/6、2/6、4/10、1/8 的请求以 `curl (56)` 被重置、或 **40 s 收不到一个字节**；直连（`--noproxy`）与走代理都这样，说明不是本机代理。非 CJK 查询的评分路径在这次改动前后**逐字节相同**，所以这不是排序改动带来的。暖请求 4–6 s，暂停后的第一个请求 25 s（被 `-m 25` 截断）；同一天 `site_health_check.py` 里 `/api/lessons` 也以同样方式掉线，所以**不止搜索**。
- **机制不在这条 issue 里，在 `#4072` 的复核**：响应是**全缓冲**的（first_byte ≈ total，1–2.7 s），worker 算完才一次性写；一旦这次计算超过约 3 s，中间盒/链路层就按静默超时掐断，表现为 `exit 56` / `http_code 000`、**连响应头都没到**。判别实验（同一条 issue）：同样慢的请求换成 `Accept: application/json` 就 100% 稳定；`initialize`、`get_lesson`、快 BM25 命中都稳。→ **修法是"别让首字节晚于约 3 s"，不是"让客户端等更久"。**

## 3. 可复用的判据

1. **`TTFB` 与 `total` 分开量**，才能说清是 worker 还是路径：大 total 小正文 = 路径；TLS 完成后的长 TTFB = worker。
2. **机器上有代理时 `time_connect` 量的是代理**（本例 `127.0.0.1:7890`）。先看 env，再解释 connect。
3. **"三份拷贝一致"要比较模式文本，不只是替换串。** 卡号规则能漂移，正是因为门禁只比了后者。
4. **第二台机器必须和尖峰同时。** 不同时的对照只能说明"那时不慢"。
5. **卡号是形状不是位数**：13–19 连写、4-4-4-4（及 4-4-4-4-1..3）、4-6-5、4-6-4。
6. **词表测试钉住的负例是真门禁。** `assert "mico" not in tokens` 抓到的是投稿课程里的内部平台名与内网域——脱敏不只管凭据，也管内网标识。
7. **生成物冲突的解法是固定顺序**：merge `main` → 冲突文件一律取 `main` 的版本 → 重跑索引/`lessons.json`/页面/排名快照/OKF/证据表/词表 → 提交。手改生成物会过不了"生成器是 no-op"那条测试。
8. **"命中率 15/20" 与 "哪几条差一名" 是两个读数。** 报告只列掉出前三的行时，第二名的行在任何一次运行里都不存在——那正是这 4–5 条一直没人看的原因。
9. **维护者代推外部 PR 时 `git push origin` 推到的是 upstream 同名分支**，不是 author 的 fork；推到 fork 要显式加 remote（本轮踩过一次，同名分支已删）。
10. **加一个客户端到 `AGENTS` 是"八处一起改"。** `#4083` 一次点红六个文件里的八条断言：客户端表、README 的 Installer-managed 行、Quickstart（两种语言 + 页面 fallback）、注册选择器 + 两个词条、包 README 的名单。它们不是噪音，而是"清单在哪些面上对外承诺"的完整列表——逐条改完再谈"加个目标"。
11. **手写的数字挨着生成块，会像生成块本来不会漂那样漂。** `/install/` 的 "Show the ten supported clients" 压在十一行表上。修法是把数字也交给生成器（`render_summary`），不是改这个数字。
12. **用户导出的设置不能越过 `--home <沙盒>`。** `DSH_HOME` 让安装器自己的测试写掉了真实的 `~/.dsh/AGENTS.md`（截成 35 字节）。判据：`--home` 是"把这个目录当家"，所有派生路径都必须落在其下。
13. **`--verify` 的"完整"必须覆盖新目标。** 新目标不进检查表时，删掉它的文件仍报"安装完整性：完整"——接入一个新客户端的最后一条清单应该是"它进不进 verify"，而不是"它写不写文件"。
14. **发布链路的三段要分开看**：tag 有没有被建、workflow 有没有被 dispatch、npm 上到底有没有那个版本。0.8.1 前两段都有、最后一段靠人补；0.9.0 三段自动，但 `release` environment 的**批准**仍是设计里的人工闸门——它是给人看的，不是漂移。
15. **"谁决定排序"和"谁判断相关性"必须是两个变量。** 二者共用一个 `decidesOrder` 时，把 CJK 的排序改成按展开词，就同时把别名喂进了相关性地板，#2358 那条"自信的错误答案"当场回归（`chrome-relay` 又出现在 `wsl2 landlock 文件系统沙箱` 里）——门禁在同一个 run 里抓住了。改一个看似只影响排序的开关，要问它还被谁读。
16. **修期望不能抬 floor。** 把可接受集合补全（residual 5 行）确实让 hit@1 变漂亮，但那不是搜索变好；floor 只按**代码**改动抬（CJK top-3 16→18，floor 15→18），多出来的两行当余量。
17. **"取前 N 行"的守护测试会被任何一次插入重抽。** 加一门英文课就让 `index-and-trust-shape.test.mjs` 的 CJK 占比从 20.6% 掉到 19.5%、红在 20% 阈值上——而它要守的性质（排除逻辑不是空转）当时正被几百个 token 行使着。**钉住性质，别钉住百分比**：阈值降到 10% 并写下"为什么是 10%"。
18. **缺字段和"没实现这个字段"在调用方看来是同一件事。** `misakanet_register` 只在复用路径返回 `reused: true`，新建节点的路径干脆不带这个键——于是"我以为在续期、其实拿到了新身份"没有任何信号。契约里**可选**的布尔值，等于没写。
19. **一个布尔值要被调用方读到，它得出现在三处**：响应体、`outputSchema`、以及给人看的文档。`#4119` 三处一起改，验证方式是给线上的 `tools/list` 看 `outputSchema`（不产生节点、零副作用）。
20. **"读一页"的脚本会把自己的盲区写成数字。** `question_autopilot` 单次 `per_page=100` 让 54 条问题变成"12 open question(s)"，而它的 digest 还会因为找不到旧页而每周新建一份——**同一处缺陷同时污染了计数和去重**。判据：任何"the open backlog"的读法都必须翻页，翻页函数只写一次。
21. **一次失败的网络读，不能变成一句事实。** 覆盖率测量没有重试时，7/12 的问题被记成"未测"；加上 3 次退避后是 1/47。**读失败要么重试，要么原样写"读不到"**——这与 Rule 4 是同一条，只是从面板搬到了脚本里。
22. **"常驻"文档需要一个稳定身份。** 5 份同名 digest 的根因是去重靠单页搜索；修法是让去重也翻页、保留**最老**那份（它带着评论历史）、其余关闭并指向它。判据：任何会被定期重写的 issue/评论，必须有**一个**能重新找到它的键（标题前缀 + 翻页），而不是"上一页里出现的第一份"。
