## 117.1 这一轮做了什么：stdio 的 intake 回执开始说实话

**问题（#3577，§116.7.3 那条契约 bug）**——查深一层后，发现它比"两边形状不一样"严重：

| 事实 | 证据 |
|---|---|
| stdio 的 `misakanet_submit_intake` **只写本地队列** `data/contribution_queue.jsonl` | `misakanet/server/handlers/submit.py` → `scripts/contribution_queue.submit_contribution` |
| **没有任何代码把本地队列变成 GitHub issue** | 全仓只有 `scripts/contribution_review.py`（维护者手动 CLI）与 `scripts/emit_intake_receipt.py` 读它 |
| 回执里的 `dedup_key` **不是队列存下的那个键** | handler 另算了一个 SHA-256（`kind:problem:source`），队列存的是它自己的 SHA-256（脱敏后的 title/message）——**它指向一个不存在的存储** |
| `misakanet_me_inbox` **代理远端 worker**，看不见本地条目 | `misakanet/server/handlers/inbox.py` 打的是 `{base}/api/inbox` |
| 工具描述**本来就在说真话** | `misakanet/server/tools.py`：「Side effects: writes to data/contribution_queue.jsonl」——**是回执在撒谎** |
| `scripts/` **不进 wheel** | `pyproject.toml`：`include = ["misakanet*"]` → pip 装的用户调这个工具直接 ImportError |

合起来一句话：**stdio 的"提交"是个只写本地文件的假成功**——报告永远到不了 MisakaNet，回执却说"提交了，去查收"。

**修法（远端优先 + 诚实的降级）**，照抄仓库已有的 `handle_submit_usage` 形状（同一个文件里就有"远端优先 + 不可达时本地降级"的先例）：

1. `handle_submit_intake` **先走网络**（`misakanet.remote.call("misakanet_submit_intake", …)`）——hosted worker 是唯一能把 intake 变成 issue 的地方；
2. 网络不可达 → 落本地队列，回执写明 `delivery=local_queue`、`note` 说"没有到达 MisakaNet，没有工单可查"；
3. `poll_hint` 统一成**对象**（`tool` / `argument` / `how` / `recheck_after_seconds`），与 hosted endpoint 的形状逐字段一致——远端那条原样透传，本地那条同构，一个 reader 吃两条路；
4. `dedup_key` 改成**队列真正存下的那个键**（不再另算一个）；
5. `misakanet_me_inbox` **先查本地队列**再代理远端——本地条目的轮询承诺才成立。

**没有本地队列又没有网络**（= pip 装 + 断网）→ 明确报错、`submitted: false`，**不再报假成功**。

新增开关 `MISAKANET_INTAKE_DISABLE_REMOTE=1`，与 `MISAKANET_USAGE_DISABLE_REMOTE` 同形。

## 118.1 先修工具：CF 授权到底坏在哪

上次那句 `chmod: cannot access '/home/<user>/.cfut_<token>'`
和随后的 `Invalid format for Authorization header`，**是同一件事的两面**：

| 症状 | 真因 |
|---|---|
| `chmod` 说文件不存在 | chmod 的目标是 `~/.cfut_<token>`——**token 被当成了文件名**。那个文件从没被创建过，所以 chmod 必然失败。 |
| `wrangler` 报 "Invalid format for Authorization header" | `~/.cloudflare_api_token` 里存的是 `<cfut_…>`——**连尖括号一起粘进去了**。`wrangler` 拿到的是带尖括号的那个字符串，不是 token 本身。 |

修法一行：把尖括号去掉，`chmod 600`。

> **token 按已泄漏处理**：它出现在上一卷的终端输出和会话日志里。改用 wrangler 的 OAuth 凭据
> （`~/.config/.wrangler/config/default.toml`）做日常操作，token 请到 Cloudflare 后台轮换。修完 `wrangler whoami` 认得账号 `misakanet`
（6b92325b505f2b76aec49e9fe4195d31），`wrangler d1 insights`、`wrangler d1 execute`、D1 REST API 全通。

**顺带纠一个 §117.6 写错的事实**：`~/.cf_oauth_token.json` 不是 wrangler 的凭据位置，**它过期与否跟 wrangler 无关**。
真正的凭据在 `~/.config/.wrangler/config/default.toml`（OAuth token，scopes 里带 `d1:write`、`workers:write`）。
也就是说 **token 从来不是唯一的路**——上一卷"只差一个 token"的判断下得太早了。

> 教训：§114.2 那段 `printf '%s' '<token>' > …` 是**示例**，被当成模板执行了，
> 于是尖括号进了文件、token 进了文件名。以后这类命令要么写明"把 `<token>` 换成真值"，
> 要么就别把尖括号留在可复制的行里。

## 118.5 改法：两个根因，两个最小改动

### ① `storeList` 改成范围谓词（`workers/register-proxy-sw.js`）

`WHERE key LIKE ?1 ESCAPE '\' …` → `WHERE key >= ?1 AND key < ?2 …`。
上界 = 前缀的最后一个码位 +1（`unsolved:lesson:` → `unsolved:lesson;`）。
**68,892 行 → 6 行。**

两处语义变了，写在代码注释里而不是"应该没问题"：
- `LIKE` 对 ASCII 大小写不敏感，范围比较是**精确**的。本仓库写的 key 全是小写
  （`unsolved:lesson:`、`proxy:…`、`keepalive:…`），两者等价——但只有大小写不同的 key 从此不再被列出。
- `LIKE` 的通配符 `%` `_` 由 `escapeLike` 中和；范围形式没有通配符，所以"按字面匹配前缀"这个语义反而更准。

### ② `/api/analytics` 上边缘缓存（按受众分键）

这个端点的答案是"七天滚动聚合"，不是"此刻的状态"，所以**少算几次**比"算快一点"对。
用仓库已有的写法（`/api/lessons`、`/api/activity`、`/api/funnel` 都是这一套）：`caches.default` +
`ctx.waitUntil` 写回，TTL 120 秒。

**两个受众必须两个条目**：边缘缓存按 URL 索引，**不按 `Authorization`**。所以维护者条目用
`/api/analytics?audience=maintainer` 这个键，匿名条目用 `/api/analytics`——
否则维护者的 `knowledge_gaps`（**别人原样发来的失败查询**）会被端点缓存直接发给下一个匿名调用者。
维护者的响应还带 `Cache-Control: private`，免得中间代理把这段原话存下来转手发人。

### 120.2 一个必须记下来的坑：CDN 的缓存键里没有 Authorization

带 `Authorization: Bearer …` 的请求实测拿到 **`cf-cache-status: HIT`** 和**匿名负载**。
CDN 的缓存键是 URL，不含凭据。今天无害，因为**生产的 worker 根本没配 `MCP_TOKEN`**：
`/api/health` 报 `hasMcpToken: false`，`wrangler secret list --name misakanet-register-proxy`
只有 `REGISTER_TOKEN`——所以 `isMaintainerRequest()` 恒为 false，维护者分支目前是**死代码**。

但**谁一旦给 worker 设了 MCP_TOKEN**，维护者请求会被 CDN 的匿名条目喂到，于是**永远看不到
`knowledge_gaps`**（不会泄露给别人，但功能会静默消失）。worker 里修不了这个——请求在到达
worker 之前就被 CDN 答了。两条可行解：维护者用 `/api/analytics?audience=maintainer` 这个 URL
（worker 的 Cache API 键本来就是它，`private` 响应 CDN 不存），或者在 zone 上加一条
