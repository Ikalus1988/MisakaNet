### 91.2 CI 红的两个面，和上一卷「第五个 SSOT」是同一件事

PR #3259 的 run `38642712164`：六个矩阵腿 + `audit` 全红。失败点只有两条断言：

```
tests/test_install_smoke.py:119   assert len(documented) == 10, sorted(documented)
                                 → assert 11 == 10
test_mcp_tool_count_ssot.py       the hosted worker serves 8 tools but
                                 docs/integrations/status.md asserts 7
```

上一条提交 `4099b9b1` 的标题说工具计数已经是「第五个 SSOT」。**这次证明了那句话还差两层**：
那条提交修的是 worker 那一面（JS 套件），而红的是另外两面。其中一面的数字
（`docs/integrations/status.md` 的 7）**恰恰是那条提交自己的 commit 正文里提到的** ——
它写下了「五个面」，却没有把其中一个面的数字改过来。

实测面数（`docs/mcp.md` 11 个 stdio 工具、worker 8 个 hosted 工具）：

| 面 | 数量 | 谁断言它 |
|---|---|---|
| `docs/mcp.md` | 11 | `test_install_smoke`（读文档）|
| `workers/register-proxy-sw.js` | 8 | `versions-endpoint.test.mjs` |
| `docs/integrations/status.md` | 8 | `test_mcp_tool_count_ssot` |
| `.codex-plugin/plugin.json` | — | `test_mcp_capability_parity` |

**教训比结论重要：上一轮的验证跑了 Python 套件、没跑 worker 套件，于是漏了一面；
这一轮的验证跑了 worker 套件（`stress` 转绿）、没跑本地文档面，又漏了一面。**
计数是跨语言、跨文档的，没有哪一套件能覆盖全部四个面。这不是第三次该重新设计的地方，
而是**每次新增工具时，那四行断言都要一起看**的清单问题。

### 91.3 `test_me_inbox.py` 那个 import：第一遍测法是错的，结论差点跟着错

那个文件末尾有

```python
if __name__ == "__main__":
    pytest.main([__file__, "-v"])
```

但模块里没有 `import pytest`。直接跑文件，第一次实测得到的是：

```
ModuleNotFoundError: No module named 'misakanet'
```

**根本没走到 `pytest.main`。** 如果就此收工，commit 里就会写「跑起来是 `NameError`」——
一句我并没有测到的话。加上 CI 的 `PYTHONPATH=.` 再跑，才是真相对照：

| 树 | 结果 |
|---|---|
| 带 import，`PYTHONPATH=.` | **15 passed in 1.28s** |
| 不带 import，`PYTHONPATH=.` | `NameError: name 'pytest' is not defined` |

> **规则（承 §90.4.1）：验证一个修复之前，先确认你真的走到了那条路径。**
> 第一次的失败被更早的一层挡住了，而那一层恰好是本机环境与 CI 的差异。
> 这与「反例必须让退回旧写法真的变红」是同一条：**没测到 ≠ 测过。**
