## 6. 已踩过的坑（务必先读，能省数小时）

### 6.1 git 线协议不稳 → 用脚本，别手搓
`git fetch/push` 会 `Failed to connect to github.com port 443 after 134359 ms`（REST 通常仍可用）：

```bash
python3 scripts/gh_push_via_api.py --branch <br> --message-file <msg> <files...>   # 建/推分支
python3 scripts/gh_push_via_api.py --branch main --direct --message-file <msg> <file>  # 快进 main
```

带"分支不在 base 上就拒绝"的保护；token 取 `GITHUB_TOKEN`/`GH_TOKEN` 或 `~/.git-credentials`，从不打印。

### 6.2 推 main 前必须先 commit 再 rebase
远端有 bot 提交（leaderboard 快照）时几乎必然要 rebase；**有未提交改动时 `git rebase` 直接拒绝**，
而 `append → fetch → rebase → commit` 这种顺序会在 rebase 处静默断链（本轮犯过两次）。

### 6.3 PR 的 CI 卡在 `action_required` 不是失败
PR 分支被 **bot 推过**（`Auto-Merge Docs PRs` 合 main、`/fix-dco` 的 force-push）后，该 PR 的所有
run 会变成"等待批准"。用 API 批量放行：

```bash
POST /repos/Ikalus1988/MisakaNet/actions/runs/{run_id}/approve    # owner 权限，返回 201
```

**bot 每再推一次就重新挂起**（本轮批了约 90 个 run）。另外 `PUT /pulls/{n}/update-branch` 能解开
`mergeable=unknown` 卡死（#1627 就是这么合掉的）。

### 6.4 "CodeQL 报错 + 请查看状态页面"
在**被 bot 推过**的 SHA 上，GitHub 会建 check-suite 但不跑任何 check run（实测两个 SHA 上 13 个
suite 全是 `failure` + `runs=0`）——PR 上的 CodeQL 就会显示失败并给那句提示。
**GitHub 状态页是好的**（All Systems Operational）。按 §6.3 放行即可。

### 6.5 release-please 的 `signoff` 是字符串，不是布尔
`schema` 里那行 `"signoff": true` 是 **JSON Schema 布尔子模式**（"任意值合法"），**不是推荐值**。
填 `true` 会让 main 上每次 push 都 `release-please failed: The format of 'true' is not a valid
email address with display name`。正确写法：`"signoff": "misakanet-bot <bot@misakanet.dev>"`。
改这个文件后**立刻看它自己的下一次运行**（我这次是用户先看到告警）。

### 6.6 版本 bump 是两三条线，别只 bump 一条
release-please 管 **PyPI 线**（`pyproject.toml` + `server.json` 的 pypi 条目）；**registry 线**
（`server.json.version` + `glama.json.version` + API.md/JOIN.md）走
`python3 scripts/align_versions.py --registry X`。`--check` 是门禁。

### 6.7 站点部署：自动，但**异步**
misakanet-web 由 Cloudflare Workers Builds 在**任何 push main** 后自动部署（约 45 秒）。
验证：`curl -sI https://misakanet.org/<路径>/`（**注意尾斜杠**：无尾斜杠返回 307，不是 404）。
`docs/**` 里的 md 会直接以 URL 提供，是最快的"是否重新部署"探针。

### 6.8 其他环境坑
- npm/npx 写不了 `~/.npm` → 加 `--cache ./.npm-cache`。
- CF MCP / registry 授权：每个 CF MCP 产品有独立 OAuth 域，WSL 回调不通 →
  `python3 scripts/cf_mcp_auth.py --server cloudflare-observability [--refresh|--verify]`。
- 本地 `pytest` 报 `mcp.server.mcpserver` 之类导入错误 = 本地依赖漂移，**以 CI 为准**。
- `data/lessons.json` 只能由 `update_lessons_json.py` 生成（日常由 `update-lessons.yml` 定时跑）；
  手工生成用 `misakanet-index.py` 会静默回滚线上统计（#1374）。
