### dsh.so L5 web-smoke failure — root cause + fix

**Symptom (dsh.so page `https://www.dsh.so/artifact/misakanet/`, test ID `misakanet-20260902T192254Z`, profile `l5-web-smoke`, dsh `0.1.2-alpha.1`):**

```
L5.1_INSTALL_PASSED_SANDBOXED — Sandbox install passed  ✓ Passed
L5.2_WEB_BOOT_READY          — Web boot ready          ✕ Failed
  detail: plugin tree failed to load
L5.3_HTTP_SERVED             — HTTP endpoint served    ✕ Failed  (cascaded)
```

**Root cause:** `cordis.patch.yml` shipped with v2.23.0 declared an inert Cordis insert:

```yaml
- insert:
    - id: misakanet
      name: misakanet
```

The `apply()` was a no-op, so the insert only existed to populate `pluginInventory`. dsh.so's l5-web-smoke harness re-applies the bundle patch through a second path, so the same id is fed to the Cordis Loader twice. dsh `0.1.2-alpha.1` is strict: any second `insert` with an existing id is a fatal startup error (`TypeError: duplicate loader entry id: misakanet`). That surfaces on the verdict page as the literal "plugin tree failed to load" detail.

Locally reproduced with `DSH_HOME=/tmp/dsh-home-...` against the v2.23.0 tarball; same stack.

**Fix (commit `199c9746`, tag `v2.23.1`):**

| File | Change |
|---|---|
| `package.json` | Drop `dsh.bundle.patch` + `dsh.client.platform` (no client bundle ever shipped). Bump version to `2.23.1`. |
| `cordis.patch.yml` | Deleted. |
| `index.js` | Keep `name` export and the no-op `apply()` so `dsh plugin add` still passes the install contract. Rewrite the top comment to explain why no Cordis contribution is made. |
| `index.d.ts` | Unchanged (already minimal). |
| `lessons/contrib/dsh-plugin-l5-web-smoke-cordis-duplicate-entry.md` | New lesson, full root-cause table + verification block. |

After the change, the plugin is installable via `dsh plugin add misakanet` (npm) or `dsh plugin --profile <name> add github:Ikalus1988/MisakaNet#v2.23.1` (git), but never becomes a Loader row — duplicate-id collisions are structurally impossible.

## Reusable pattern (for the next agent)

When dsh.so reports a verdict with text like:

- "plugin tree failed to load" → likely Cordis Loader duplicate id. Strip `dsh.bundle.patch` or rename the entry id.
- "Sandbox install failed" → likely network / GitHub codeload timeout in the sandbox. Prefer the npm channel.
- "Web boot ready" failed with no further detail → check `dsh web` stderr first, then re-run with `dsh --profile web --help`.
- "HTTP endpoint served" failed but L5.2 passed → check that `dsh plugin` reconciler activated the bundle (look for `# == <name>` in `dsh --dump-config`).

The new lesson (`dsh-plugin-l5-web-smoke-cordis-duplicate-entry`) is the canonical reference for the duplicate-id family; the older lesson (`dsh-plugin-install-github-codeload-timeout`) is the canonical reference for the install-timeout family.
