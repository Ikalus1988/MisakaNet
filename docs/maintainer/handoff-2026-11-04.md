## 1. 这一轮定下来的判断（是决定，别再重新论证）

1. **`pending-review` 是语料队列，question 不进语料队列。** 它的意思是「等着被评审成一篇课程」；
   而 question 的出口是**一个答复**。2026-11-03 实测：50 条开放的 `[Question]` **全部**带着它——
   #4238（19 文件安装器清单）和 #4239（市场流程问题）在语料队列里坐了三天。
   修法不是只改分类器：**五个路径**各自把标签加上（worker 建 issue、`intake_pipeline`、
   `mcp_http_server`、分类器、auto-review 的 shell 分支——最后这条的删除列表在 `exit 0` 之后），
   五个都得改；只改一个等于没改。判据：**一个标签的含义由消费它的队列定义**，不是由加它的那行代码。
2. **新的点目录可以是「要发布的包」，不是「工具草稿」。** 形状守卫的 `internal_artifact` 规则是为
   #3748 的临时 patch 写的，它把 `.cindy-plugin/` 一并判成了 scratch。例外做成**声明式**：
   `<!-- shape-guard: allow-new-dot-dir .cindy-plugin: <理由> -->`，按目录、必须带理由、别的目录不沾光。
   **守卫跑在受信 base 上**，所以声明支持必须先落 base（#4398），要加包的那个 PR 才能被放行——
   顺序是判据的一部分，不是流程意外。
3. **一个不写任何文件的宿主是一个真实的 target。** Cindy 的工具来自应用内插件，没有用户级 MCP 配置、
   也没有可写的规则文件；`AGENT_WRITE_PATHS.cindy` 返回空数组是**结论**，不是省略。
   `--verify` 因此需要第五个词 **「查不了」**：说「没装过」是没验证过的断言，说「就绪」是反方向的
   同一个断言。它接进 `unverified` → **退出码 2**（未知），与 1（坏了）分开。
4. **dismiss 必须留下「换哪条检查」和理由。** 上卷 §1.5 的规矩这次补齐了最后 4 条：
   #323/#324（生成的重定向目标含 CJK slug，熵启发式误判）、#320（正则已匹配 `</script\s*>`，
   且它解析的是本仓自己的 HTML）、#49（行号已漂移；唯一的 `github.com` 判断是
   `gh issue create` 自己 stdout 的 `startswith`）。API 要求重开→再 dismiss 才能写 comment。

## 4. 可复用的判据（比结论更值钱）

* **一个标签的含义由消费它的队列定义。** 加标签的代码可以写错上下文，但读它的队列会把它当成真的。
  改标签时先找「谁会因为这个标签出现」——#4238 的错误不是少了个标签，是它出现在了错误的队列里。
* **声明式例外要能被自己检查。** 形状守卫的例外写成 PR body 里的 marker，且**按目录 + 必须带理由**：
  裸 marker 不算、别的目录不沾光、没有理由就不生效。`tests/test_pr_shape_guard.py` 里三条都在。
* **「未知」需要一个自己的词。** 二值结论（就绪/坏了）会把「读不到」说成其中一半的谎；
  第五个词 + 退出码 2 是让脚本也能区分「别去修它」和「去修它」。
* **量的口径要跟用途一致。** 20 次采样说「尾巴今天没复现」，不等于「尾巴不存在」；
  #4052 保持打开，是因为「没有证据」不等于「没有」。
