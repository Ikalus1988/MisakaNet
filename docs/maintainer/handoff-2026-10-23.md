## 1. 接口全绿、页面全废：#3694 误删的两个 helper（2026-10-23）

### 现场

用户报的是"前端 api 看看连接"，现象是首页的网络活动面板写着"暂不可用"。

第一层排查（curl）结论是**服务端完全正常**：前端脚本里出现的 18 条 `/api/*` 路径全部有真实数据
（`/api/health` 200、`/api/activity` 今日 255 次、`/api/counter` 34865、5 个 `/api/insights/*` 全
`available:true`、GitHub 代理的 `/issues` 与 `/pulls` 都 200）；POST-only 的端点用**空 body 探针**
确认活着（`/api/feedback` 回 `{"accepted":0}`，所以没有写脏数据）；`OPTIONS /mcp` 预检 200 且 CORS
头正确，`POST /mcp` 带前端原样的 `MCP-Protocol-Version` 也 200。另有三个"看着像坏了其实不是"：
`GET /api/feedback` 404（本来就只收 POST）、`/api/github/repos/<REPO>` 403（前端只调它的子路径，
子路径都 200）、`/api/topics/show.json` 404（那个路径来自某堂课的标题）。

第二层（用户追问"用 Playwright 或者 computer use 自己确认一次"）结论是**坏的**：

```
GET /api/activity                        200
page errors: ["escapeHTML is not defined"]
#activity-body:    "活动快照暂不可用（站点部署早于本页）"
#latest-list:      "动态列表暂不可用"
#voices-container: "voicesLoadFailed"
```

### 根因不是两个引用，是一次"搬走"

#3694（`b108716e`）"注册表单搬到 /register/"，把**紧挨着表单**的两个函数一起删了：

| 函数 | 首页的调用点 | 后果 |
|---|---|---|
| `escapeHTML(val)` | 12 处 | 凡是渲染 JSON 的面板都在渲染时抛 `ReferenceError` |
| `readJsonResponse(response)` | 2 处（`fetchWithTimeout` / `fetchPOST`） | **每一次 JSON 抓取**都过它，于是每一次都抛 |

表单是这两个函数在首页上**唯一的"表单用途"**使用者，而首页自己的面板一直在用它们。
搬走的是表单，删掉的是函数。

### 三个机制（这才是可复用的部分）

1. **经典脚本里未定义的引用在"调用点"炸，不在"加载时"炸。** 页面正常加载、正常发请求，
   直到某一行第一次拿到数据要渲染，才抛。
2. **面板自己的 `catch` 把 `ReferenceError` 翻译成了"暂不可用"。** 而这四个字在文案里是
   **关于数据新鲜度**的断言——"站点部署早于本页"。那句话是假的：站点是新的，页面才是坏的。
3. **兜底路径和主路径共用同一个函数，所以兜底不是保险，是第二个故障点。** 实时 `/api/activity`
   挂 → 退到 `data/activity.json` → 那条路也走 `readJsonResponse` → 一样挂 → 才落到"暂不可用"
   文案。7 天曲线**根本没被请求过**：发请求的那次先炸了。

### 修法与判据

两个函数按 `/register/` 的副本**逐字节**恢复（`docs/index.html:2916`、`docs/index.html:3312`），
一处不改。判据必须是**真浏览器读 DOM 和 `pageerror`**，不是 curl。

修后线上实测（2026-10-23 01:56Z）：

```
GET /api/activity                        200
GET /api/activity/history?days=7         200
page errors: []
#activity-body:    "780 次 MCP 调用（今日） … 实时 · 3分钟前更新"
#latest-list:      五条正常渲染
#voices-container: 贡献者引语正常渲染
```

### 元教训

> **curl 全绿只能证明服务端活着。** "接口连不上"这个报法，有相当一部分其实是"页面在渲染时炸了"，
> 而这两件事在 curl 眼里一模一样。

> **一句关于数据新鲜度的错误文案，会把排查方向带偏很远。** "暂不可用"让所有人去查接口；
> 接口是好的。先看页面自己的报错，再看接口。

## 2. 没有 lint 的仓库，"调用了没定义"是系统性盲区（2026-10-23）

### 现场：12 次调用、0 次定义，而所有门禁全绿

- 仓库里**没有** eslint、没有 bundler、没有类型检查（`ls .eslintrc* eslint.config*` 无结果）；
- 唯一的 JavaScript 测试 `tests/frontend.test.js` 测的是 `docs/js/core.js`——**首页根本不加载它**；
- 于是 `escapeHTML` 被调用 12 次、定义 0 次，没有任何东西看得见。

也就是说，这类缺陷在这个仓库里**不是偶然事件，是一类没有守门人的缺陷**。

### 门禁

`scripts/check_page_scripts.py`（`scan()` 在 `scripts/check_page_scripts.py:388`）：

规则只有一条——**页面调用的名字，必须来自三个来源之一**：① 本页自己的定义；② 本页加载的脚本
（`<script src>`）的定义；③ 标准库。它不是 linter：类型、遮蔽、`this` 是别的门禁的活，
一个什么都管的门禁什么也管不住。

**能变红**（三处证据，不是"我以为它会红"）：

1. `--reverse-test`（`scripts/check_page_scripts.py:444`）注入一个"调用了没定义"的页面，必须被抓到；
2. 把首页改回修复前的样子，同一个检查必须同时报出 `escapeHTML` 和 `readJsonResponse`
   ——实测报出，exit 1；
3. 当前 595 个页面必须 0 误报——实测 0 命中，0.12 秒。

误报那一半单独钉在 `tests/test_check_page_scripts.py`（12 条）：标准全局（`alert`）不算缺失；
定义了自己调用的页面不报；正则字面量里的引号不吞文件；除法不认成正则；结束标签的四种写法都要认
（`tests/test_check_page_scripts.py:150`）。

### 写这条门禁踩到的三个坑

1. **正则字面量里的引号。** `/[&<>"']/g` 是一个**含引号的正则字面量**。按字符串扫的实现会把那个
   `'` 当成字符串的开始，一路吃到下一个 `'`——文件后半截被当成字符串丢掉，**后面所有定义都没了**。
   第一版扫描器因此在 `docs/index.html` 报出 12 个"缺失"，其中 `fetchJSON`、`fetchWithTimeout`、
   `animateCounter`、`loadStats` **全都明明在文件里**。
   解法：写一个真的分词器，用**上一个有效 token** 区分"正则字面量"和"除法"——这正是 ECMAScript
   规范给的规则。
2. **浏览器接受的结束标签比直觉多。** `</script>`、`</script >`、`</script/>`、
   `</script foo="bar">` 都合法。CodeQL 的 `Bad HTML filtering regexp` 为此报了两轮，
   **两轮都是真问题**。写窄了的后果不是"这一页没被扫到"，而是——**整段脚本不可见**，
   于是页面调用的每个名字都被报成缺失。
3. **误报方向比漏报方向更容易杀死门禁。** 一个会在正确页面上报错的门禁，活不过两次。

### 元教训

> **一个仓库里没有被任何门禁看见的缺陷类别，不会因为"没人报告"而消失。** 它会以另一个形状出现——
> 这次是"接口挂了"，而接口是好的。

> **门禁的第一版必须先证明"不误报"。** 能在正确页面上报错的门禁会被关掉，而不是被修。

## 3. 合并之后线上没更新：上线的是 `dist` 分支，不是 `main`（2026-10-23）

### 现场：PR 合并了，workflow 绿了，线上还是旧页面

`publish-dist.yml` 成功、`dist` 分支也推上去了（`9f7eb1dd`），但线上首页仍然没有修好的定义。
判据不是"workflow 绿了"，而是**直接 curl 线上文件**。

### 真因：同一个 commit，在两个分支上的同名 check 结论相反

- `dist` 提交上的 `Workers Builds: misakanet-web` 是 **failure**；
- 而**同一个 commit 在 `main` 上**的同名 check 是 **success**。

原因是 Cloudflare 那个项目配了**两个分支**：`main` 只出 **Preview**（check 输出里带 Preview URL 和
Preview Alias URL，不上线），`dist` 才是生产。而 dist 那次构建失败的时间（01:52:22Z）离 main
那次构建开始（01:52:04Z）只有 **18 秒**——两个分支的构建撞进了同一个队列。等不到自动重试。

### 处置

```bash
gh workflow run publish-dist.yml --ref main      # 产生新的 dist 提交 → 触发新的生产构建
```

21 秒后构建 success，线上随即恢复。

### 元教训

> **站点是 `dist` 分支部署的，不是 `main`。** 判断"线上换了没有"，要看 **dist 提交上的
> Workers Builds**，并且**直接 curl 线上文件**——`main` 上那个同名 check 是绿的，但它只出 preview，
> 根本不上线。

> **workflow 绿不等于线上更新了。** 中间隔着一个部署平台，而部署平台有自己的队列和失败模式。

### 顺带量到的（给下一轮省事）

- `https://misakanet.org/js/core.js` → **200**：站点的根映射到 `docs/`，所以 `docs/js/` 下的文件
  **可以直接被页面按 `/js/xxx.js` 引用**；
- 静态资源响应头是 `cache-control: public, max-age=0, must-revalidate` + ETag，
  **不会留下陈旧缓存**，改共享 JS 不需要额外的版本策略。

## 4. 留下的两笔

### 4.1 尾斜杠（这一轮顺手修了）

全站**唯一**一处指向 insights 页的链接在 `docs/privacy/index.html:201`：
`href="/insights/quickstart-events/"`——注意**不在首页**，首页只是在一句隐私说明的**注释**里提到了
那个路径。它 307 到 `/insights/quickstart-events`（200），所以链接是通的，只是多一跳。
顺带量了：四个 insights 页的带斜杠形式全部 307、不带斜杠全部 200。

已改成不带斜杠，href 与显示文本一起改：这个页面讲的是透明度，给读者看的应该是那个真正能打开的 URL。

### 4.2 共享模块：这才是这次的真根因（留给下一轮）

`escapeHTML` 现在在 **7 个页面**各有一份，`readJsonResponse` 在 **2 个页面**各有一份。
**复制粘贴就是这次事故的根因**——门禁只能发现，不能预防。治本做法是抽成 `docs/js/site.js`
（**classic script**，不是 module：这些页面都是经典脚本，module 的作用域不一样）。

这一轮没做，原因是它会动站点构建路径。下一轮要做的话，事实已经量好：

- 站点根映射到 `docs/`，`/js/site.js` 可直接引用（`/js/core.js` 实测 200）；
- 静态资源 `must-revalidate`，改它不会留陈旧缓存；
- **但仓库里没有先例**：`docs/js/core.js` 存在，而**没有任何页面加载它**——所以"页面引用本地脚本"
  这件事在本仓是第一次，要多验一遍；
- 加载顺序：classic script 要在页面内联脚本**之前**（首页的内联脚本在 `docs/index.html` 第 2112 行附近）；
- 抽完之后门禁仍然成立：`_local_script_names()` 会解析 `<script src>`，所以共享文件里删掉一个
  helper 依然会被抓到；
- 7 份 `escapeHTML` 的实现有细微差异（`String(value || '')` 与 `String(val ?? '')`），统一时要选一个；
  `??` 更保真（`||` 会把 `0` 变成空串）。

### 给下一轮的操作提醒

- 要做共享模块的话，**先在一个页面上试**（建议 `docs/index.html`，因为它的两个函数是这一轮刚补
  回的），本地真浏览器验过再推其余 6 个；
- 本地验法（这一轮用过的）：本地起 http.server 伺服 `docs/`，把 `/api/*` 反代到线上，
  这样一次能验"实时"与"快照兜底"两条路径。**反代必须带浏览器 UA**——`Python-urllib` 的 UA 被
  Cloudflare 403，而 `curl` 的放行；第一次反代全 502 就是这么来的；
- 门禁本体：`python3 scripts/check_page_scripts.py --check` 与 `--reverse-test`；改动门禁后重跑
  `python3 -m pytest tests/test_check_page_scripts.py`。
