# 改布局时的像素门禁口径：只改了要改的

**这份是一份提案，owner 可以改其中任何一条。** 它回答的是 §128.4 里挂着的问题：
#3639 / #3640 / #3641 都**故意**改布局，"像素零差异"这个口径对它们不成立——
那不是可以顺手放宽的门禁，是要单独定口径的事。

## 问题

`scripts/compare_site_pixels.py compare` 问的是**改了多少**：一页的差异像素比例超过阈值就红。
这个问法对"本来就不该动布局"的改动是对的（§125.8、§128.2）。

对一个**故意**重排的改动，它问不出该问的东西：

- 把首页的图表往前挪，页面从中间开始整体位移——"差了多少"和"我有没有改错地方"是两回事；
- 唯一能让 `compare`变绿的办法是 `--ignore-layout-shift`，那是"把门禁放宽到它变绿"，
  **它对"改了什么"一个字都不说**。

## 口径

> **作者声明允许变的区块；门禁断言框外一个像素都没有变。**

```
compare_site_pixels.py scoped --before A --after B \
    --allow index@1280x800:0,1900,1280,2400 \
    --allow index:0,0,10,10
```

- `--allow` 可重复；`page[@viewport]:x0,y0,x1,y1`，坐标是**图像坐标**（像素）；
- 不带 `@viewport` 的区域对该页的**每个**视口生效；
- **一页没有声明任何区域时，它不许变。**（和 `compare` 同一条规则，
  所以没人动过的页面不需要许可，而被人动了却没声明的页面会红。）

单位是**区块**，不是像素：声明的区域里改多少都行；声明之外改一个像素就红——
那多半是没人想动的顺手改。

## 怎么用

1. 采两遍：`capture --docs-root docs --out before` / `--out after`；
2. 看清楚改了什么：`compare --before before --after after --verbose`
   ——它**已经**打印每个差异区域的包围盒；
3. 决定哪些区域就是这次要改的，把它们的包围盒写进 `--allow`；
4. 跑 `scoped`：它证明**其余一切都没动**。

## 它不做什么

- **它不说这次改动是好的。** "只改了要改的"是**范围**的保证，不是**质量**的保证。
  改对了没有，由 DOM/语义断言（`tests/test_site_a11y_semantics.py` 等）和 review 负责。
- **它不替代 `compare`。** 「改布局」的 PR 走 `scoped`；其余的照旧走 `compare`。
  `compare` 本身一个字没动：默认容差、阈值、报告都一样。
- **它不判断设计好不好。** 折叠还是展开、表格还是列表，那是产品决定，不是门禁的事。

## 三个已定的细节（owner 可以改）

| # | 决定 | 为什么 |
|---|---|---|
| 1 | 页面变高时，**整条新增的带子**都算改动，不只是变色的那几行 | 页面长高四十行空白，这件事本身就是改动；比像素看不出来，因为另一边压根没有像素。报告把两件事分开记：`recoloured_pixels` 是颜色差，`grown_pixels` 是长出来的那截 |
| 2 | 容差照旧适用（默认 3，§128.2 实测的噪声底） | 这是**另一个问题**，不是更松的问题：通道差 1 是渲染器抖动的噪声，差 40 是改动 |
| 3 | 没有声明的页面**不许变** | 否则"忘了声明"就成了默认放行 |

## 一个已量出来的坑：跨树的噪声，和"只改了要改的"不是同一件事

这个口径要拿两棵**不同的树**去比（before 是基线树，after 是分支树），所以它会碰上
**同一棵树里量不出来的噪声**。实测（首页，390×844 视口）：

| 比较 | 任意有差的像素 | 超过容差 3 的 | 最大通道差 |
|---|---|---|---|
| 同一棵树，两次采集 | **0** | 0 | 0 |
| 两棵**内容相同**的树（副本） | **0** | 0 | 0 |
| 两棵差**一个字符**的树（改的是 HTML 注释） | **36** | **4** | **5** |
| 两棵差一段可见文本的树 | **36** | **4** | **5** |

**换句话说：只要文件的内容变了一个字节，搜索输入框的四个圆角就会变几个像素。**
那 4 个像素落在 `390×844` 上（`768`/`1280` 是 0），最大差 5 级——**超过默认容差 3**。
改的是注释还是可见文本都一样，所以它与改动内容无关。

**这不是新口径带来的**：`compare` 对同一对图报出**完全一样**的 4 个像素、也判红。

**机制**（推断，未逐条核实）：冻结样式表是在 `page.goto()` **之后**注入的
（`scripts/compare_site_pixels.py` 的 `_capture_one`），所以动画先跑过一轮；
之后 `animation:none` 把它们拉回基态，Chromium 的**分层/栅格化**因此和
"从没动画过"的状态不同，圆角的亚像素抗锯齿就差几个级别。
这类差异**不是容差能解决的**——把容差提到 5 确实能盖住它（实测），但
**#3670 证明过容差 3 能抓住 1 级的强调色改动**（`#00e5ff` → `#00e6ff`），
提到 5 就抓不住了。**单一全局容差两者不可兼得。**

**这是 owner 的决定，不是实现能替 owner 定的：**

1. **把容差提到 5**，代价是放弃 1 级颜色改动的检出（门禁仍然能抓更大的改动）；
2. **让那四个圆角变得确定**（例如把冻结样式表改成在文档之前注入，
   `add_init_script` 已经能做这件事——把 `page.add_style_tag` 换成 init script 里的
   `<style>`），代价是要改采集路径并重新测一次噪声底；
3. **不动容差**，让每个布局 PR 的作者自己声明那 4 个像素（难用，但诚实）。

**在 owner 选之前，这三个 issue 的 scoped 判定都要把这件事算进去。**

## 验证

`tests/test_pixel_scoped_gate.py`（21 条）用**造出来的像素**驱动判定，不需要浏览器：

- 声明区域内改动 → 过；声明区域外改动 → 红；
- 没声明的页面改了就红；没改的页面不需要许可；
- 页面变高、变宽、变矮——多出来或少掉的那一截都算改动；
- 容差盖住噪声、盖不住真实改动；
- 命令行的区域写法、坏写法要报错（**退 2，不是退 0**——退 0 就是放行一切）；
- `main()` 走真的 PNG 文件：过的时候退 0，红的时候退 1。

**16 条变异，每条都对着它的目标测试：** 15 条变红（13 条因断言，2 条因异常逃出），
1 条反向对照（只改注释）保持绿，**0 存活**。

变异清单在 `tests/test_pixel_scoped_gate.py` 的断言里就能读出来——
哪条断言钉住哪一处判定，是一一对应的。
