## 2. 为什么 handoff-2026-09-11 §4.1 的归因是错的（本轮最重要的一条）

那份 handoff 说 "SSOT 机制没覆盖 `index.html`"。**现象对，归因错一半**。真实根因是
**占位符替换会消耗占位符**：第 1 轮把 `{{LESSONS_COUNT}}` 写成数字并打印成功，
第 2 轮起 `if "{{LESSONS_COUNT}}" not in text: continue` 永远命中 → 什么都不做，也不报错。

证据：`ARCHITECTURE.md:35` 停在 2026-09-05 物化的 `358+`；`README.md` 从未真正带过标记；
仓库里同时存在一个**幂等但从未被任何 workflow/测试调用**的 `sync_lesson_count.py`。
按原方案把 `index.html` 加进 `COUNT_MARKER_DOCS`，只会制造第 3 个"第一次正确、之后永不更新"的受害者。

**修法原则（本轮）**：数值用"每轮重新匹配"，不用"替换标记"；匹配不到 = 硬失败。

## 6. 已踩过的坑（本轮新增，能省时间）

1. **占位符替换是一次性的**（§2 + lesson `ssot-marker-replacement-runs-once`）。看到"把标记换成值"
   的同步器，先问"第 2 轮做什么"。
2. **同一文件多行注册表写入会互相覆盖**：每行都用扫描时读到的文本替换 → 后一行覆盖前一行。
   表现：工具打印 `docs/index.html: 3 site(s) → 378`，磁盘上仍是 `435`。按文件累积、最后写一次。
3. **模式必须能匹配自己写出的文本**：用要求 `+` 的正则校验、却写成不带 `+` 的结果 → 第一次成功后
   永久喊"句子被改写了"。测试里用"不动点"断言一次挡住。
4. **`GITHUB_TOKEN` 永远推不了 `.github/workflows/**`**（`without workflows permission`）：
   别让 bot 去维护 workflow 文件里的值，改成运行时读。而且只有第一个值变化的那天才会炸，
   还会丢掉整次生成（lesson `github-token-cannot-push-workflow-files`）。
5. **未闭合的 `<!--` 会把整篇 markdown 正文注释掉**（GitHub 渲染成空白），并让"取第一行做摘要"
   的提取器把 `<!-- provenance:` 当成摘要发布到 meta/搜索结果。19 篇中招。不变式：
   `text.count("<!--") == text.count("-->")`（lesson `unclosed-html-comment-hides-markdown-body`）。
6. **判断"某个 workflow 步骤到底跑没跑"，读 YAML 条件不算数**：用
   `GET /actions/runs/{id}/jobs` 看每个 step 的 `conclusion`（`skipped` vs `success`）。本轮靠它发现
   release-please 的后三步**从来没跑过**；下载 run 日志（zip）能看到 release-please 原话。
   弱网下这些 API 会 `IncompleteRead`，要重试。
7. **改了 scheduled workflow 一定要 `workflow_dispatch` 跑一次**：本轮第一次真跑就抓到两个 bug
   （workflows 权限、push 竞态），否则要等到次日 cron 才知道。
8. `git push` 本轮大部分可用，但常被 bot 快照打成 non-fast-forward：稳妥顺序是
   `fetch` → `rebase` → `push`，失败就重试（本轮给每日 job 也加了 `concurrency` + job 内 rebase 重试）。
   偶发 `unable to get credential storage lock ... Permission denied` 无害；
   `GnuTLS recv error (-110)` 需要重试，或改用 `scripts/gh_push_via_api.py`。
9. **`issue-quality-gate` 的判据在 issue 正文，不在评论**：它按正文里的 `AC/验收标准` + `[ ]` 复选框
   打 `ready` 或 `needs-ac`。只发评论等于没补 AC；而且它**只加不删**标签，于是会出现 `needs-ac` 与
   `ready` 并存的怪状态（本轮已修 gate：满足条件时清掉过期那个）。
10. **HOL 的 `plugin-scanner` 判定已经读源码确认（不是猜）**：它是 PyPI 包
   `codex-plugin-scanner`（HOL 的 guarded-repository 用它，每 main push 重扫），判定函数是
   `_is_safe_relative_asset = is_safe_relative_path(plugin_dir, value, require_prefix=True,
   require_exists=True)` —— 于是 `interface` 资产必须**以 `./` 开头**，**且** `(plugin_dir / value)`
   真实存在。而它跑的 `PLUGIN_DIR=.`（**仓库根**，见 run 日志）。所以：
   外链 HTTPS 不行（`require_prefix` 直接拒），`.codex-plugin/assets/…` 这种写法也不行
   （从仓库根解析不到），**只有 `./.codex-plugin/assets/…` 同时满足两条**。
   `pip download codex-plugin-scanner` 就能读到这些判据——第三方扫描器报错时先读它的源码。
11. 给仓库加图片资产前先用 PIL 压一下：三张图原样入库是 8.9 MB（含 6 MB 动图），
   `thumbnail` + 首帧 PNG 后 **968 KB**，对插件清单足够。
12. 本地 `pytest tests/` 仍有 3 失败 + 2 收集错误，**全部是环境漂移**（`mcp.server.mcpserver`、
   `mcp.Client`、需要公网的 `test_semantic_smoke`），与本次改动无关；其余 1100+ passed。以 CI 为准。
