### 2.3 变异工具自己也不可信——一次是它的错，一次是我的错

**工具报 MISMATCH，而那个 MISMATCH 是假的。** `read_text`/`write_text` 做 universal newline
转换，读到内存的 CRLF 变 `\n`、写回即 LF；于是被变异文件的行尾被改掉，而校验拿 LF 文本的
哈希去比 `shutil.copy2` 已按字节还原好的 CRLF 文件——**报了一个它自己造成又自己修掉的损坏**。
一个在没损坏时报损坏的工具比没有工具更糟：它训练你跳过那个本来能抓到真损坏的检查。
改成字节读写、按原有 EOL 写回、字节对字节校验之后，**我立刻引入第二个洞**：9 个变异里 3 个
报「变异没生效」，因为我把「每次从磁盘重读」写成了「每次从原文改」，后一条读到的是上一条
留下的文件。

> 所以工具必须分开报——脚本现在分别输出 `mutation produced no change` 与 `[FAIL] <label>`。

## 4. 待办与决策

### 4.1 #2959 的三条 windows 腿：根因是绕开了 `posix_shell`，本轮已修并加了门禁

`test (windows-latest, 3.11/3.12/3.13)` 失败于 `test_workflow_hygiene.py` 的两个 tag-pin 用例，
**来自 #2959 第一个提交 9ef165cc**。对照 run `37592032941`（9ef165cc）失败的是同样两个用例，
所以不是加界改动引入的。

根因不是 CRLF（我先猜错了，见 §4.1.2）：`_run_pinning_check` 直接 `subprocess.run(["bash", ...])`，
而 `windows-latest` 上 PATH 里的 `bash` 是 `C:\Windows\System32\bash.exe`——**WSL 启动器**，
该镜像没装任何发行版。日志里的证据是断言失败时带着一段 UTF-16LE 横幅
（`W\x00i\x00n\x00d\x00o\x00w\x00s...`）：子进程打印的是这句话，**脚本根本没跑**。

仓库里 `scripts/posix_shell.py` 正是为这个失败建的（2026-09-21，当时「~20 个测试在每个 PR 上
变红」），15 个测试文件已经在用 `require_posix_shell()`。缺的不是 helper，是**没有任何东西要求
新测试用它**。修法：改用 helper + 脚本路径转正斜杠（反斜杠在 shell 里是转义符）。

**新门禁 `tests/test_shell_invocations_are_portable.py`**：禁止任何测试把字面量 shell 名交给
`subprocess`，除非它声明 POSIX-only。3/3 变异全红。

**CI 实测（run `37603815929`，2026-10-07）**：三条 windows 腿由红转绿——
`3.11 pass 7m34s`、`3.12 pass 7m47s`、`3.13 pass 5m50s`，macOS 三条同样全绿，
四条必需检查（DCO / `audit` 8m8s / `gate` / `test (ubuntu-latest, 3.11)` 3m53s）全绿。
**这是这个 PR 第一次整矩阵无红。**

#### 4.1.2 一条我写了、量了、然后被自己删掉的规则

门禁的第一版还有第二条：禁止用 `write_text` 写 `.sh` 而不 pin `newline="\n"`。理由是
`write_text` 在 Windows 上发 CRLF，而 bash 把 `\r` 当成 token 的一部分。我**确实量到了**
Linux bash 上 CRLF 脚本会失败：

```
crlf_probe.sh: line 1: set: -: invalid option
crlf_probe.sh: line 2: syntax error near unexpected token `$'do\r''
```

但这条规则在仓库里会命中 **9 处**，而这 9 处**在 `windows-latest` 上全是绿的**——
包括断言 `returncode == 0`、断言桩 `gh` 确实被调用的那些。**如果 CRLF 在 Git Bash 下是致命的，
那些腿应该是红的。** 它们不是。所以那条推论（从 Linux bash 外推到 Git Bash）不成立，
规则被我删掉了，而不是把措辞改软。

教训和 §2.3 是同一条：**「我测到了」不等于「我测的是这件事」。** 那次测的是 Linux bash，
写进规则的却是 Git Bash。9 处误报就是这条推论的价格。

`test_workflow_hygiene.py` 里仍然保留 `newline="\n"`，但注释已改成如实陈述：
它让字节与平台无关，**不是**在这里修掉了一个观测到的失败。

#### 4.1.3 变异验证在新门禁里抓到的洞

第一条变异（把字面量 `"bash"` 放回 `test_workflow_hygiene.py`）**没被抓到**。
原因是我把豁免写成「文件里 import 过 `posix_shell`」——而那个文件确实 import 了它，
**import 过 helper 和这处调用用了字面量是两回事**。豁免只保留给 POSIX-only。
改完 3/3 全红。这是本任务里第四次出现同一个形状，只是这次在我自己刚写的门禁上。

## 7. #2971：密钥扫描器报告「没发现密钥」的对象是它没打开过的文件

`scan_credential_patterns` 与 `check_env_var_handling` 都以 `except Exception: return hits` 结尾，
空列表与「读过了、里面没有」不可区分。临时树上的复现（修复前）：

```
readable   -> [{'file': 'leak.js', 'line': 1, 'type': 'GitHub personal access token'}]
chmod 000  -> []      ← token 还在盘上
directory  -> []
dangling   -> []
```

**后两种不是假想输入**：`Path.rglob("*.js")` 会吐出名为 `*.js` 的子目录和悬空符号链接，
两者都会经 `secret_scan_files()` 到达扫描器（这一点在测试里断言过，不是假设）。

修法：`_read_for_scan` 只把 `OSError` 翻译成 `UnreadableScanTarget`；
调用方把它计入 `errors`（退出码非零——**这里的红是可操作的，warning 不是**）；
并且成功那行改成 `elif not unreadable:`——**一次没有发生的扫描不该打印体检报告**。

3/3 变异全红（还原静默兜底 / 去掉成功行的条件 / 把未读记成 warning），脚本按字节还原。

### 7.1 为什么测试**没有**用 `chmod 000`

issue 的复现用的是 `chmod 000`，但这个探针有两种方式会什么都没测：
root 本来就能读；**本仓检出在 `/mnt/c`（DrvFs），Windows 文件系统直接忽略 POSIX 权限位**——
实测 `chmod 0o000` 之后扫描照样返回了那条命中。这样的测试会绿着通过而不证明任何事。
目录与悬空符号链接在任何 uid、任何文件系统上都读失败，覆盖同一个 handler。
`test_a_chmod_000_probe_is_not_used_because_it_cannot_fail_reliably` 把这个理由留在原地，
免得下一轮有人重新推一遍。

另有一个用例断言这道门**仍然可以是绿的**，所以新规则不能靠「永不通过」来满足。

## 14. §3.1 第 5 步抓出来的新缺陷 → #2983

**`scripts/sync_answered_questions.py:113` 有 `problem[:2000]`——算 dedup 哈希前把 problem 静默截到

实测（用脚本自己的 `fnv1a_hex`）：

| issue | problem 长度 | hash(完整) | hash(前 2000) | 线上返回 |
|---|---|---|---|---|
| #2774 | 2000 | `ec796fef` | `ec796fef` | `ec796fef` → `answered=true` |
| #2819 | 1949 | `de0a7b6a` | `de0a7b6a` | → `answered=true, answer=1866 chars` |

注脚：这本身是一次**静默截断**，与刚落地的 `mcp-intake-silent-truncation-family` 同族。
那篇课文说"fixed four times, each time at the next cap"——这是第五次，而这次截掉的是**去重键本身**。

## 16. 三条会让人误判的环境事实

1. **线上 schema 仍带 `minProperties`** —— #2967 的 worker 修复已合入 `main`（`266b6056`）但**尚未部署**。
   **合了 ≠ 上线。** 查线上行为前先确认部署状态。
2. **不要伪造 `CF-Connecting-IP`** —— 用 TEST-NET-3（`203.0.113.x`）会让 `tools/call` 返回
   **403 / Cloudflare error code 1000**，而 `initialize` 仍然 200。很容易误判成"服务坏了"。
3. **本机 shell 的代理变量是给 GitHub 用的**，对 `misakanet.org` 要显式 `env -u http_proxy …`。
   `tools/call` 还会超时，curl 超时给到 240s（实测单次约 5–120s）。
