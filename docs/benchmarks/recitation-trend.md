# Recitation benchmark: what it measured, and why it is paused

> Moved here from `README.md` on 2026-11-26. The README keeps the three claims a reader needs — that
> the run is paused, where the last snapshot is, and what the number does **not** prove — and this page
> keeps the setup, the whole trend, and the per-run files. Nothing was dropped in the move; the
> generated block below has the same anchor comments and the same producer.

One narrow question: **when you hand a model a lesson, how much of that lesson comes back?** The
metric is `lesson_hit_rate` — the share of the injected lesson's commands reproduced in the answer.

Read the setup before the number:

- the scenario in this benchmark is each lesson's own title (`load_all_scenarios` builds it from
  `scene = (title or problem)`), not a failure a user would type;
- the injected lesson is **that same lesson** (`load_lesson_context` recovers the stem from the
  scenario string);
- **no retrieval call is made** — `score_response` counts how many of that lesson's commands appear in
  the answer, and nothing in the script touches a search path;
- **correctness is not checked.**

So it measures the **recitation** half of RAG: necessary for MisakaNet to help, and **not evidence
that search finds anything**. `METRIC_SUMMARY` in `scripts/benchmark_workers_ai.py` is the one-sentence
SSOT that the public claim must carry verbatim.

## The run is paused

Two independent runs of ≈500 scenarios each on 2026-09-22: **46.1%** with the lesson pasted in,
**23.3%** without. The weekly workflow's `schedule:` trigger was removed with the demotion, so nothing
regenerates this page on a timer — `tests/test_benchmark_claims.py` checks the workflow for a live
`schedule:` and fails if one comes back.

What remains is the last snapshot plus its dated record:
[`latest.json`](latest.json).
