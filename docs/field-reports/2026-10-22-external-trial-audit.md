> **来源.** 一个第三方 agent 在**安装之前**审了 npm 元数据与安装器源码，然后写下了四段判断。
> 这四段判断被拆成四个 issue（#3689 / #3690 / #3691 / #3692），本报告是它们的**共同出处**。
>
> **已脱敏.** 无凭据、无主机名、无个人身份；路径一律写成 `<home>` / `<workspace>`。
> 引用的是试用者的**原话**（译自英文原文），逐字保留的是判断本身，不做美化。
>
> **环境.** 试用者审的是 npm 上的 `@misaka-net/misakanet-setup`（当时 `latest = 0.5.6`，2026-09-19 发布）。

## 2. 这四段判断的分量

试用者没有提错任何一条事实——包括路径级细节（`~/.openclaw/openclaw.json`、工作区 `AGENTS.md`）。
**它错过的是"有没有开关"，不是"发生了什么"。**

这一点决定了修法的形状：

- 第 1 条是**我们自己的话**造成的风险（描述），改描述即可，不必加功能；
- 第 2 条是**默认路径**造成的风险（不预告），改首屏输出即可，不必改行为；
- 第 3 条是**发版流程**造成的风险（没人 bump、没人打 tag），改流程即可；
- 第 4 条是**代码行为**造成的风险（脱敏靠模型自觉），只能改代码。

**四条的修法不应该一样。** 前三条是"我们怎么说话 / 怎么走流程"，最后一条是"代码到底做了什么"。

## 3. 仍然诚实地说不清的那一半

第 4 条里，**内部表名**（`orders_2024` 这类业务标识）**机械脱敏不了**：
代码能确定性处理的是路径、邮箱、密钥、IP；表名与业务语义只能靠"别把会话转录和业务细节粘进去"约束。
所以最终的承诺必须写成两段，不能写成一句"已自动脱敏"——否则就是拿一句假话换一句真话。
