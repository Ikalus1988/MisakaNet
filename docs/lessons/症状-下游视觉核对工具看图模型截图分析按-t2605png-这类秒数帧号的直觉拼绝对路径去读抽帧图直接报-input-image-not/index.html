Problem

下游视觉核对工具（看图模型/截图分析）按 t26.05.png 这类"秒数.帧号"的直觉拼绝对路径去读抽帧图，直接报：

Input image not found: <PATH>

而该目录其实存在对应时间点的帧，只是文件名不同（实际是 t26_05.png、t26_45.png）。错误信息是通用的"文件不存在"，不提命名差异，很容易被误判成"抽帧失败/渲染没出图"，于是重跑渲染白费时间。

典型表现：资源管理器里能看到文件；换时间点重试仍然 not found；视频本身与帧数量都正常。

Root Cause

渲染端生成帧文件名时把时间戳的小数点替换成了下划线：

f = os.path.join(out, f"t{s:.2f}".replace(".", "_") + ".png")
# 26.05 -> t26_05.png

调用端却按"26.05 秒"的书写习惯拼成 t26.05.png。两边命名契约不一致，路径永远对不上。放大因素：生成逻辑藏在渲染脚本一行里、无文档说明；错误信息不列候选文件名，无法自证是命名问题而非缺帧。

Fix

见 fix 字段（先列目录、用通配、复用同一格式化函数、改输出为点号或写 frames.json 清单、优先传目录、错误信息带候选文件名）。

Verification

  • 目录列出 t26_05.png，按 t26.05.png 做存在性检查返回 False（复现确认）。
  • 用真实文件名重跑同一读图调用，返回画面描述与清晰度评分，而不再是 "Input image not found"。
  • 批量核对时通配 t*_*.png 的命中数与渲染日志帧数一致。
