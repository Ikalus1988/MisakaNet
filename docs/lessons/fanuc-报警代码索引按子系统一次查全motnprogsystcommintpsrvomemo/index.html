Problem

检索的形态是「我手上有一条报警码，我要知道它意味着什么、有多严重、哪篇课讲过」。这些知识在 fanuc 域的 36+ 篇课程里都有，但散在各处：搜 KAREL INTP-316 能命中，是因为有人恰好把代码写进了正文；没有一份按 子系统 + 代码组织、一次可以查全的入口。现场工程师只能逐篇翻，或者去论坛找没有出处的代码表。

Root Cause

报警代码是短字符串，语义检索对它的判别力弱（见 rag-alarm-code-mandatory-recall：查 SRVO-023 会返回无关文档）， 命中与否取决于代码有没有被某篇课的正文或 tags 收录。而课程是按故障故事写的，不是按代码写的—— 于是「输入一条报警 → 定位含义与课程」这条最短路径一直没有入口。

Solution

下表每行三件事：代码 → 典型含义 → 严重等级，外加依据（本语料里讲它的那篇课，点开可核对）。 只收录有依据的代码；含义一律照抄来源，不补充来源没有写的解释。

严重等级怎么读

等级语义来自 fanuc-alarm-severity-guide 的级别表；没有逐码等级 来源的行标 未验证，不猜：

标记级别现场含义
切伺服SERVO / SERVO2 / SYSTEM瞬停并切断伺服电源（红）——急停类属此列
停机器人PAUSE / STOP / ABORT减速停或动作锁定，伺服保持（黄/红）
仅告警WARN / NONE / 信息不停机（白/蓝）
未验证——来源没给等级，本表不猜

已知缺口（本表刻意留白的）

  • SRVO-023 —— 在语料里只作为检索样例出现过 （rag-alarm-code-mandatory-recall），没有任何来源给出它的含义， 所以本表不收。补充条件同上：一条现场记录或一篇讲它的课程，两者其一。
  • 等级列大量「未验证」是如实反映：来源给了含义的多数没给逐码等级。补齐的办法是现场按 fanuc-alarm-severity-guide 的颜色/级别观察后回填，而不是照抄 论坛代码表（本语料的 fanuc-alarm-code-reference 自述「基于通用报警 体系整理，非原帖附件内容的直接复制」，它的含义列可用，等级列不可引用）。

查到代码之后

  1. 按 fanuc-alarm-severity-guide 的恢复流程走：记录 → 查历史 （MENU → Status → Alarm）→ 根因 → RESET → 复验；先修根因再按 RESET。
  2. 红色（切伺服/系统级）先查安全回路与 DCS 配置 （fanuc-dcs-safety-configuration）。
  3. DCS 参数改动要 4 位密码，改完必须 Apply（SYST-212 就是没 Apply）。

Verification

  1. 本索引能被检索到（AC：「把代码写进正文与 tags」）：
   python3 search_knowledge.py "INTP-316 alarm"

预期：结果里出现本索引或 fanuc-karel-intp-316-call-error-motion-lock。

  1. 每行依据可核对（任取一码，如 SRVO-049）：
   grep "SRVO-049" lessons/contrib/fanuc-dcs-safety-configuration.md

预期：打印出含 SRVO-049 的那一行（退出码 0）—— 表里的每个码都能在它「依据」列指向的文件里找到。
