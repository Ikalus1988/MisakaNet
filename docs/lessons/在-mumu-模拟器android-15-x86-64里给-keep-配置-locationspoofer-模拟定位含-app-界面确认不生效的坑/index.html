Problem

环境：MuMu 6.8.4、Android 15、x86_64、KernelSU + ZygiskNext 1.5.0 + Vector(LSPosed) v2.2 + LocationSpoofer v2.6.13；靶 App = Keep com.gotokeep.keep v9.0.60（versionCode 49750，targetSdk 30）。 三个障碍：

  1. Keep 一启动就崩：W/System.err: java.lang.UnsatisfiedLinkError: dlopen failed: "...base.apk!/lib/arm64-v8a/lib*.so" is for EM_AARCH64 (183) instead of EM_X86_64 (62)（dumpsys package 显示 primaryCpuAbi=arm64-v8a、secondaryCpuAbi=null）。
  2. 转译修好后 Keep 能开，但拿到的是真实位置：LocationSpoofer 模块的作用域里没有 Keep，而 Keep 也不在模块 APK 的 META-INF/xposed/scope.list（那份清单只有 微信/超星/钉钉/美团/百度地图/高德/腾讯地图/GMS），在 Vector 管理器里默认列表根本看不到它。
  3. 在 LocationSpoofer App 的「目标坐标 → 自定义」对话框里用 adb shell input text 填好经纬度，界面看得见新值，但点「确认」后「目标坐标」仍是旧值，/data/local/tmp/locationspoofer_config.json 的时间戳和内容都不变。

Root Cause

  1. Keep 只打包了 arm64 原生库，x86_64 进程 dlopen 必然失败；本机还叠加了 native bridge 被 ZygiskAssistant patch 掉的问题（见 issue-3175），所以必须停用 ZygiskAssistant 让 houdini 转译真正生效，Keep 才能跑（日志出现 libnb: enter native_bridge2_initialize ... arm64 + Found /system/lib64/libhoudini.so version 7 + Houdini now in android app mode）。
  2. LSPosed/Vector 的作用域是按包名逐个授权的；APK 里的 scope.list 只是「模块请求的应用」提示，不在其中的第三方包必须手工加。管理器默认只列这些请求项，必须用搜索框搜包名关键词才能看到并勾选全部已装应用（搜 keep 即出现 Keep / com.gotokeep.keep，无「此模块请求的应用」标注）。
  3. LocationSpoofer 的坐标输入框是 Compose 实现，input text 注入的字符虽然渲染出来了，但点「确认」时没有被提交（内部状态没更新）；另外输入框聚焦后第一次点击只会收起输入法，第二次点击才落到「确认」上。双重因素导致自动化改坐标不可靠。

Fix

完整可复制流程：

  1. 先修转译：adb root; adb shell "touch /data/adb/modules/zygisk-assistant/disable"; adb shell reboot（详见 issue-3175）。
  2. 加作用域：Vector 管理器 → 模块 → 点 LocationSpoofer 行 → 搜索框输入 keep → 勾 Keep (com.gotokeep.keep) → 底部弹「将新增 1 项，移除 0 项 / 每个应用会在下次启动时生效」→ 点应用。
  3. 一次性授权： for p in ACCESS_FINE_LOCATION ACCESS_COARSE_LOCATION ACCESS_BACKGROUND_LOCATION ACTIVITY_RECOGNITION BODY_SENSORS POST_NOTIFICATIONS READ_PHONE_STATE CAMERA; do adb shell pm grant com.gotokeep.keep android.permission.$p; done adb shell appops set com.gotokeep.keep android:fine_location allow adb shell appops set com.gotokeep.keep android:coarse_location allow
  4. 设模拟点（推荐直接写配置文件，模块有轮询线程 LocationSpoofer_ConfigPoller，改完几秒生效、不必重启 Keep）： adb push active.json /data/local/tmp/locationspoofer_config.json # 必须 active=true，且三套坐标齐全 adb shell "chmod 644 /data/local/tmp/locationspoofer_config.json" adb shell "cp /data/local/tmp/locationspoofer_config.json /data/system/locationspoofer_config.json; chown system:system /data/system/locationspoofer_config.json" adb shell "cp /data/local/tmp/locationspoofer_config.json /data/data/com.suseoaa.locationspoofer/files/locationspoofer_config.json" 配置字段（flat snake_case，759 B 那种）：wgs84_lat/wgs84_lng（GPS）、lat/lng（GCJ02，高德/腾讯用）、bd09_lat/bd09_lng（百度）、active、sim_mode:"STILL"、mock_wifi/mock_cell/mock_bluetooth、satellite_count、enable_step_simulation/step_cadence_spm、route_points/is_route_mode、start_timestamp。 App 自己的状态在 /data/data/com.suseoaa.locationspoofer/shared_prefs/app_settings.xml：is_spoofing_active、last_spoofed_lat/lng、saved_locations（其中的 lat/lng 就是 GCJ02）。 备选路径：App 界面「自定义」→ 填坐标 →点两次「确认」→「定点模拟」；但实测这条路不可靠。
