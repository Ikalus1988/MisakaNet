A file: dependency on a directory omitted from the tarball installs a dangling node_modules symlink

Domain: nodejs · Evidence E2 — Local smoke reproduced
npmarboristpackagingtarballsymlinkfile-protocol

Summary

A published package declares a dependency on a directory that is **not** in its own

Problem

A published package declares a dependency on a directory that is not in its own tarball:

{
  "name": "repro-parent",
  "dependencies": { "native-addon": "file:./packages/native-addon" },
  "files": ["index.js", "package.json"]
}

The report (issue #3299, npm 11.20.0) was: read-only inspection found a dangling node_modules symlink to the omitted directory, and the question is whether this layout is a known trigger for Arborist rebuild.js #addToBuildSet failing with

Cannot destructure property 'package' of 'node.target' as it is null.

Evidence status of that crash, stated up front: the dangling symlink is reproduced below; the crash itself is not. On both npm 11.12.1 and the exact reported npm 11.20.0, install / rebuild / ci complete successfully over this layout. Treat the crash attribution as unconfirmed, and the dangling-link part as measured.

Root Cause

What is confirmed by reproduction:

  1. npm pack only ships what files (or the default rules) allow. With files: ["index.js", "package.json"], packages/native-addon never enters the tarball, while the file: dependency declaration does (it lives in package.json).
  2. On install, npm materializes the file: dependency as a relative symlink. The consumer's node_modules ends up with:
   native-addon -> repro-parent/packages/native-addon

The target directory is not inside the installed repro-parent (the tarball omitted it), so the symlink dangles. The lockfile simultaneously records the link and a target entry with no package data: "node_modules/repro-parent/packages/native-addon": {}.

Where the reported crash would come from, in Arborist's source (@npmcli/arborist/lib/arborist/rebuild.js, #addToBuildSet):

const { package: pkg, hasInstallScript } = node.target

If a link node with target === null ever reaches the build set, that destructure throws exactly the reported message. In the repro here, that shape does not occur: the dangling link is not represented as a null-target node during install/rebuild, and a lockfile that references a link whose target entry is missing is rejected earlier with a clean EMISSINGTARGET error (see Verification). Which npm/arborist version or tree shape does put a null-target link node into the build set is not established by this reproduction — evidence insufficient.

Solution

Publisher-side correction for the part that is reproduced (the dangling link): the file: dependency must not point outside the published surface. Either

  1. ship the directory — add it to files:
   "files": ["index.js", "package.json", "packages/native-addon"]

or

  1. stop declaring it as file: — depend on the published native-addon package by version range, or make it a bundledDependency that is genuinely present in the tarball.

Verified effect of (1): with packages/native-addon in files, the pack listing contains the directory, the install-time symlink resolves, and require('native-addon') returns the expected value. No dangling link remains.

This lesson does not claim a fix for the reported #addToBuildSet crash, because the crash was not reproduced.

Verification

tarball 安装双侧复现（npm 11.12.1；files 省略依赖目录 vs 包含）：

$ python3 - <<'PY'
import json, os, subprocess, tempfile
def build(omit):
    d = tempfile.mkdtemp()
    os.makedirs(os.path.join(d, 'packages', 'native-addon', 'build'))
    open(os.path.join(d, 'packages', 'native-addon', 'package.json'), 'w').write(json.dumps({"name": "native-addon", "version": "1.0.0"}))
    open(os.path.join(d, 'packages', 'native-addon', 'build', 'addon.node'), 'w').write('x')
    files = ["index.js", "package.json"] if omit else ["index.js", "package.json", "packages"]
    open(os.path.join(d, 'package.json'), 'w').write(json.dumps({"name": "repro-parent", "version": "1.0.0", "dependencies": {"native-addon": "file:./packages/native-addon"}, "files": files}))
    open(os.path.join(d, 'index.js'), 'w').write('')
    return d
for omit, label in [(True, 'fault'), (False, 'fix ')]:
    src = build(omit)
    pack = subprocess.run(['npm', 'pack'], cwd=src, capture_output=True, text=True, timeout=120)
    tgz = pack.stdout.strip().splitlines()[-1]
    inst = tempfile.mkdtemp()
    open(os.path.join(inst, 'package.json'), 'w').write(json.dumps({"name": "consumer", "version": "1.0.0", "dependencies": {"repro-parent": f"file:{os.path.join(src, tgz)}"}}))
    subprocess.run(['npm', 'install', '--no-audit', '--no-fund'], cwd=inst, capture_output=True, text=True, timeout=120)
    link = os.path.join(inst, 'node_modules', 'repro-parent', 'node_modules', 'native-addon')
    if not os.path.exists(os.path.dirname(link)):
        link = os.path.join(inst, 'node_modules', 'native-addon')
    print(f'{label} side: symlink={os.path.islink(link)} target_resolves={os.path.exists(link)}')
PY
fault  side: symlink=True target_resolves=False
fix   side: symlink=True target_resolves=True

故障侧：files 省略 packages/ 时安装后 node_modules 链接悬空（target_resolves=False）； 修复侧：把目录写进 files 后同一链接解析正常。注意本检查复现的是悬空链接，#3299 报告的 Arborist 崩溃在 npm 11.12.1/11.20.0 上均未复现（见正文 Evidence status）。

Notes

  • file: dependencies are resolved relative to the installed package root, not to the repository that was packed. Anything they point at must therefore be inside the tarball.
  • Version note: the intake names npm 11.20.0. The repro above was run on both 11.12.1 and 11.20.0 via npx -y npm@11.20.0; the dangling-link behaviour is identical on both.
  • If you are chasing the #addToBuildSet crash specifically, the decisive question is what puts a link node with target === null into the build set — this repro shows the omitted- directory layout alone does not do it on 11.x. Do not claim the crash is fixed by the files change without a repro of the crash itself.
