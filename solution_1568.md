# Vertex AI 成本归因：BigQuery billing exports + traces + Gemma 混合计费

## Problem

Vertex AI 成本难以归因，导致团队无法准确追踪模型训练和推理的成本，影响预算管理和成本优化决策。

## Root Cause

1. **缺乏成本聚合视图**：Google Cloud Billing 数据分散在多个服务中，缺乏统一的成本视图
2. **缺乏请求级别追踪**：无法将成本直接关联到具体的 Vertex AI 请求
3. **Gemma 混合计费复杂性**：Gemma 模型的成本计算涉及多种计费方式（按请求、按令牌等）

## Fix

### 1. 设置 BigQuery Billing Exports

```sql
-- 创建 BigQuery 数据集用于存储 billing 数据
CREATE SCHEMA IF NOT EXISTS `project_id.billing_data`;

-- 创建 billing 导出表
CREATE TABLE `project_id.billing_data.gcp_billing_export_v1_YYYYMM`
PARTITION BY DATE(_PARTITIONTIME)
AS
SELECT * FROM `bigquery-public-data.gcp_billing_export.v1_YYYYMM`
WHERE service.description = 'Vertex AI';
```

### 2. 按项目/模型聚合月度成本

```sql
-- 月度成本聚合查询
SELECT
  project.id AS project_id,
  service.description AS service,
  sku.description AS sku,
  SUM(cost) AS total_cost,
  DATE_TRUNC(usage_start_time, MONTH) AS month
FROM
  `project_id.billing_data.gcp_billing_export_v1_*`
WHERE
  service.description = 'Vertex AI'
GROUP BY
  project.id, service.description, sku.description, month
ORDER BY
  total_cost DESC;
```

### 3. 关联 Vertex AI Traces

```sql
-- 关联 Vertex AI 请求日志
SELECT
  b.project.id AS project_id,
  b.sku.description AS model,
  b.cost,
  t.request_id,
  t.input_tokens,
  t.output_tokens,
  t.latency_ms
FROM
  `project_id.billing_data.gcp_billing_export_v1_*` b
JOIN
  `project_id.vertex_ai_logs.request_logs_*` t
ON
  b.usage_start_time = t.timestamp
WHERE
  b.service.description = 'Vertex AI'
  AND DATE(_PARTITIONTIME) = '2023-11-01';
```

### 4. Gemma 混合计费注意点

1. **按请求计费**：
   ```sql
   -- 按请求计费的成本计算
   SELECT
     COUNT(DISTINCT request_id) AS request_count,
     SUM(cost) AS total_cost
   FROM
     `project_id.billing_data.gcp_billing_export_v1_*`
   WHERE
     sku.description LIKE '%Gemma%'
     AND DATE(_PARTITIONTIME) BETWEEN '2023-11-01' AND '2023-11-30';
   ```

2. **按令牌计费**：
   ```sql
   -- 按令牌计费的成本计算
   SELECT
     SUM(input_tokens) AS total_input_tokens,
     SUM(output_tokens) AS total_output_tokens,
     SUM(cost) AS total_cost
   FROM
     `project_id.vertex_ai_logs.request_logs_*`
   WHERE
     model_name LIKE '%Gemma%'
     AND DATE(_PARTITIONTIME) BETWEEN '2023-11-01' AND '2023-11-30';
   ```

## Verification

   ```sql
   FROM
     `project_id.billing_data.gcp_billing_export_v1_*`;
   ```

2. **验证成本关联**：
   ```sql
   -- 检查成本与请求日志的关联率
   SELECT
     COUNT(DISTINCT b.invoice.month) AS billing_months,
     COUNT(DISTINCT t.timestamp) AS log_months,
     COUNT(DISTINCT b.invoice.month) -
       COUNT(DISTINCT CASE WHEN t.request_id IS NOT NULL THEN b.invoice.month END) AS missing_months
   FROM
     `project_id.billing_data.gcp_billing_export_v1_*` b
   LEFT JOIN
     `project_id.vertex_ai_logs.request_logs_*` t
   ON
     DATE(b.usage_start_time) = DATE(t.timestamp);
   ```

3. **验证 Gemma 混合计费**：
   ```sql
   -- 检查按请求和按令牌的成本一致性
   SELECT
     SUM(b.cost) AS billing_cost,
     SUM(t.input_tokens * 0.0000001) + SUM(t.output_tokens * 0.0000002) AS estimated_cost
   FROM
     `project_id.billing_data.gcp_billing_export_v1_*` b
   JOIN
     `project_id.vertex_ai_logs.request_logs_*` t
   ON
     b.usage_start_time = t.timestamp
   WHERE
     b.sku.description LIKE '%Gemma%';
   ```
