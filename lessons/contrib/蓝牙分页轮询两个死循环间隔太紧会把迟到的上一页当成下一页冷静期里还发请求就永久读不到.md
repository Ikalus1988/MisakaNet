## Problem

电池功率读数停住不更新（`reading` 一直不刷新），日志里偶发一串帧校验失败；改间隔、改超时都只是让症状变少，没有根治。

## Root Cause

1) 0.18s 间隔太紧：第 0 页和第 1 页都是 60 字节，响应帧里不带地址，只能靠「当前正在等哪一页」配对。间隔太短时迟到的第 0 页会被当成第 1 页 → 帧校验不过 → `reading` 不更新 → 功率停住。
2) 冷静期窗口位置错了：`discardUntil` 期间还允许发新请求，新请求的响应落进窗口被丢掉 → 又超时 → 又开新窗口，形成「丢一次响应就永远读不到」的死循环。

## Fix

```swift
// 1) 0.18s → 0.35s（仍小于一轮页超时，够快）
private let pollInterval: TimeInterval = 0.35

// 2) 发请求前先检查冷静期，窗口内绝不发
func pollTick() {
    if Date() < discardUntil { return }
    sendNextPage()
}
```
原则：分页协议没有地址字段时，**「等哪一页」这个状态必须和请求严格配对**，任何可能乱序的因素（间隔、重发、超时补发）都要先算清楚。

## Verification

连续跑 10 分钟：`帧校验失败` 计数不增长、功率每轮都刷新；人为制造一次超时后能自愈（不会永久停住）。
