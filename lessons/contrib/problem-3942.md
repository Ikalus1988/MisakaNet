## Problem

分析入口的扩展名白名单已收敛成「单一声明表」（程序/二进制/蓝图/变量/存储器表/IO 六类），但收集与分组层仍各写各的手写白名单——批量 zip 分组只认其中三类，存储器报告文件全被挡在分析器外，对应容量列**整列 N/A**（数据明明在备份包里）。声明层的契约测试锁住了表本身，却没锁使用方。

## Root Cause

新增分析维度时只改了声明表和部分入口（文件夹导入、zip 解析器），其余入口（批量 zip/targz/rar 分组闸、tar 解析、单台逐文件分派、Rust 侧解压白名单）各留一份手写扩展名组合，没有横扫。「修一类入口必须横扫所有入口」在 UI 布局上犯过一次，收集层又犯——因为声明层测试给了「已锁住」的错觉。

## Fix

1. 全部收口到单一声明判定函数（6 处手写白名单逐一替换）；
2. 加**使用方契约锁**测试（源码级）：收集/分组层禁止出现手写扩展名布尔闸（`endsWith('.ls') && / ||` 形态指纹）、关键闸口调用单一声明的次数下限、跨语言侧（Rust）白名单必须含全部分析扩展名。
契约锁的要点：锁「使用方的写法」而不只锁「声明的内容」。

## Verification

vitest 全量含 3 例契约锁；真机 173MB 备份包全量批量：目标列有值 187/187（修复前 0/187）；三入口一致性全量 3727 目录 0 不符；Rust 侧 77 测试全绿。
