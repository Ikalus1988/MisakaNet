## Problem

给「控制器最高/平均温度」加字段，只改 App 侧会出现三种不一致：

| 漏掉的地方 | 症状 |
|---|---|
| 服务端落盘白名单 | 本机 `trips.json` 有温度，NAS 那条 `rides.jsonl` 没这个 key，换机/重装恢复后全变成 `--` |
| `TripStore.trip(from:)` 手工映射 | 从 NAS 读回来的记录永远是 `--`（同 P28：漏 `movingMs` 时均速永远 `--`） |
| `RideSessionSnapshot` | App 被杀后恢复的行程统计从 0 重算（温度最高值只剩恢复之后那段） |

## Root Cause

骑行记录是「本地 JSON + NAS JSONL + 快照」**三份序列化**，字段集合必须一模一样，但三处都是手工维护（白名单 + 逐字段映射 + 可选属性），编译器不会提醒：新增字段漏了就是 nil，能编译、能跑、只是数据缺一半。

## Fix

当成**一个改动**做，顺序固定：

```
UplinkRide 加字段
  → server.js 落盘白名单同步
  → TripStore.trip(from:) 补映射
  → Trip 加 Optional 字段（默认 nil，老记录照旧能解码）
  → 需要跨重启的统计再进 RideSessionSnapshot（同样给默认值，别抬 schema 版本）
```

另配一个自检脚本：grep 新字段名应该命中 4~5 个文件，少于这个数就是漏了。

## Verification

走完一轮「记录 → 上传 → 删本地 → 从 NAS 恢复」：三个来源的字段值一致；`grep -rn ctrlTempMaxC` 覆盖 4~5 个文件；老记录（没有该字段）仍能正常解码。
