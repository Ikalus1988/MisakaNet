## Problem

同一次会话里踩到**四次**，两种完全不同的症状，同一根因。

**症状 A：校验全过，退出码却是 1。**

```
检查了 9 个课程文件，共 144 条断言
全部通过 ✓
UnicodeEncodeError: 'gbk' codec can't encode character '\u2713' in position 5: illegal multibyte sequence
```

断言一条没失败，只是最后那行 `全部通过 ✓` 打不出去 —— 但异常发生在 `main()` 里，于是 `raise SystemExit(main())` 拿到的是异常而不是 `0`，整次校验以非零退出。

**症状 B：测试代码看似写错，堆栈却指向标准库。**

21 条单测报 `9 failures + 6 errors`，错误是 `TypeError: argument of type 'NoneType' is not iterable`。被调用处明明是 `self.assertIn("拒绝认领", result.stderr)` —— `result.stderr` 是 `None`。翻 stderr 才看到：

```
File "<PATH>", line 1045, in _bootstrap_inner
File "<PATH>", line 1599, in _readerthread
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xbf in position 0
```

## Root Cause

Windows 上 Python 的 `sys.stdout`<PATH>` 未重定向时按 locale 编码 cp936（GBK）。打印不在 cp936 里的字符（`✓`、emoji、部分中文标点）直接抛 `UnicodeEncodeError`；而它偏偏发生在"报告成功"的那一行，于是**成功的运行被判成失败**。

`subprocess` 侧则是编码不对称：调用方写了 `encoding="utf-8"`，子进程仍按 cp936 输出字节 → 读线程里 `UnicodeDecodeError`。异常发生在**读线程**，不会回到调用点，调用方只看到 `result.stderr is None`，于是断言报 `NoneType is not iterable`，把人往"测试写错了"的方向带。

## Fix

1. 入口处两个流都 reconfigure：`sys.stdout.reconfigure(encoding="utf-8", errors="replace")`，`sys.stderr` 同理（或设 `PYTHONIOENCODING=utf-8`）；
2. 子进程显式统一编解码：`subprocess.run(..., capture_output=True, text=True, encoding="utf-8", errors="replace")`，并让子进程环境的编码设置与之一致；
3. 退出码语义分层：业务拒绝=1，工具自身坏了=2，让"打印失败"不再伪装成"业务失败"；
4. 断言写成 `result.stderr or ""`，别让 `None` 变成测试失败。

## Verification

在 cmd / PowerShell 直接运行、以及把输出重定向到文件，两种方式各跑一次：全部通过时 exit 0；故意失败一条时 exit 1；打印 `✓` 与中文都不抛异常；subprocess 场景断言 `result.stderr` 非 None 且含预期文本。

cmd 直接运行与重定向到文件各一次：全过 exit 0、故意失败 exit 1、打印 ✓ 与中文不抛异常、subprocess 的 stderr 非 None
