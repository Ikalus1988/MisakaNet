## Problem

一套数值引擎用「与官方 Excel 工具逐行对拍 405 行 0 偏差」作验收门槛，长期视为口径可信。后来发现**输入提取层**有 bug（某系统变量数组多槽位解析时后槽位的零值覆盖了活动槽位真值），导致关键输入恒为 0——但对拍依然 405 行 0 偏差通过，golden 数据、下游判定、报告全都"自洽地错着"，数百行判定档实际偏离真值。

## Root Cause

对拍验证的形态是「同一批输入喂两边（脚本 vs Excel），比输出」——它只锁**公式层**，不锁**输入提取层**。输入提取 bug 若两边同源（golden 就是坏提取器产出的），对拍恒绿。golden 自证：golden 由同一提取管线生成 → 提取错则 golden 同错 → 横扫恒过。这是「自己跟自己对」的循环验证。

## Fix

输入真值独立判据（真值抽样/第二提取链）+ 修复配探针断言命中行值

## Verification

真值抽样：抽查 N 台设备的已知设定值，提取值逐一对得上（本例 50kg 真值曾被提取成 0）；重生成 golden 后公式对拍仍 0 偏差 + 全链对拍 0 偏差；判定翻案清单显式列出（本例 218 行翻案：伪影消除与真问题浮出分开统计），历史产物按物主决定是否回改。
