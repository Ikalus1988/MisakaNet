## Problem

Claude Code agents using MCP tools rapidly consume context windows through raw tool outputs. A single Playwright snapshot costs 56 KB, 20 GitHub issues cost 59 KB, and a 500-line access log costs 45 KB. With 81+ tools active consuming 143K tokens (72%) before the first message, tool responses quickly exhaust the remaining 200K context window, causing sessions to hit performance walls after approximately 30 minutes.

## Root Cause

Each MCP tool call dumps raw, unprocessed data directly into the context window from both directions — tool definitions consume tokens on the way in, and unfiltered outputs (log files, API responses, snapshots) consume tokens on the way out. The system captures and includes all raw data generated by tool interactions without filtering or compression mechanisms.

## Solution

Context Mode is an MCP server that intercepts tool outputs through a PreToolUse hook and processes them in an isolated subprocess sandbox:

1. Each `execute` call spawns an isolated subprocess with its own process boundary where scripts cannot access each other's memory or state
2. The subprocess runs code and captures only stdout, while raw data (log files, API responses, snapshots) remains in the sandbox and never enters conversation context
3. For knowledge bases, the `index` tool chunks markdown content by headings while keeping code blocks intact, then stores them in SQLite FTS5 virtual tables using BM25 ranking algorithm
4. When `search` is called, it returns exact code blocks with heading hierarchy instead of summaries
5. The `fetch_and_index` tool extends this to URLs by fetching, converting HTML to markdown, chunking, and indexing without raw pages entering context
6. Installation via Plugin Marketplace with `/plugin marketplace add mksglu/claude-context-mode` followed by `/plugin install context-mode@claude-context-mode`, or MCP-only via `claude mcp add context-mode -- npx -y context-mode`

## Verification

Validated across 11 real-world scenarios with measured compression ratios:

- Playwright snapshot: 56 KB → 299 B
- GitHub issues (20): 59 KB → 1.1 KB
- Access log (500 requests): 45 KB → 155 B
- Analytics CSV (500 rows): 85 KB → 222 B
- Git log (153 commits): 11.6 KB → 107 B
- Repo research (subagent): 986 KB → 62 KB (5 calls vs 37)

Over a full session: 315 KB of raw output becomes 5.4 KB. Session time before slowdown extends from ~30 minutes to ~3 hours. Context remaining after 45 minutes: 99% instead of 60%.

## Notes

Ten language runtimes are supported: JavaScript, TypeScript, Python, Shell, Ruby, Go, Rust, PHP, Perl, R. Bun is auto-detected for 3-5x faster JS/TS execution. Authenticated CLIs (gh, aws, gcloud, kubectl, docker) work through credential passthrough where the subprocess inherits environment variables and config paths without exposing them to conversation. The system achieves 98% context reduction by applying the same compression principle used in Cloudflare's Code Mode (which compressed tool definitions by 99.9%) to the tool output direction instead.
