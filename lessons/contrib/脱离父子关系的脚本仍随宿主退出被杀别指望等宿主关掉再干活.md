## Problem

要在一个 Electron 宿主（DeepSeek Harness）完全退出之后，对它的 node_modules 跑一次 pnpm install（宿主运行时会锁住已加载的原生模块）。做法是写个"守夜"脚本：用 WMI `Win32_Process.Create` 拉起，脱离父子关系，循环检测宿主进程消失，然后开始安装。结果脚本**在宿主最后一个进程退出的那一刻被杀掉**——日志恰好停在“宿主进程已清空”那一行，后面“第 1 轮 install 开始”一个字没写。注意它并不是启动即死：宿主运行期间它活得好好的，还能每 30 秒写心跳。

## Root Cause

WMI 创建的进程确实换了父进程（挂在 WmiPrvSE 下），但它仍可能落在与宿主相同的 **Job Object** 里。只要 Job 设置了 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`（Electron 应用与其派生的辅助进程常这么做），最后一个 Job 成员退出时 Job 关闭，**所有仍在 Job 里的进程一起被杀**——包括看起来已经"独立"的那个。所以“换父进程”和“脱离 Job”是两件事，前者不等于后者。

## Fix

要么换真正的独立宿主，要么换顺序：\n1) **计划任务/服务**：由 Task Scheduler 或 Windows 服务在指定时刻拉起，不属于宿主的 Job（注意注册计划任务通常需要提权）。\n2) **另一个终端里手工跑**：让用户自己在独立窗口执行安装脚本——最简单也最稳。\n3) **绕开安装本身**（本次最终采用）：零运行时依赖的包不必走 pnpm，直接把 tarball 解到 node_modules，`pnpm install --lockfile-only` 同步账本即可，全程不需要宿主退出。\n判据：如果守护进程在“目标进程消失的瞬间”停止写日志，几乎就是 Job 连带；可以先用一个只写时间戳的探针脚本验证它能否跨越宿主的生死。

## Verification

探针脚本在宿主启动/退出前后都能持续写日志（跨越生死存活超过一个退出周期）；或安装流程在宿主未退出的情况下完成且版本核对通过。
