## Problem

接前一条「硬杀→冷启动恢复集耗尽」经验（同场景续篇）：按其修法把恢复集目录改名挂起后，虚拟机器人仿真器确实进入启动流程，但**始终不就绪**；且示教器仿真屏的所有输入（真实点击/键入、PostMessage 霰弹全子窗柄）都无反应。排查中发现规律：**同一输入通道在「启动任务活着」的实例上完全有效**（能答完首开配置问答链），在「启动任务已断言中止」的实例上一律落空——屏是死帧，输入没有接收者。

## Root Cause

1. **输入是否生效取决于接收任务的死活，而非输入通道/坐标/句柄**：示教器仿真屏由控制器侧启动任务驱动；任务一旦被断言中止（如网络 PAL 层 `ntpal.c` 断言、"Task asserted: Abort task N"），屏幕只剩最后帧，任何输入（含 PostMessage 直达窗柄）都进不了已死的任务。判据：「虚拟机器人状态」窗的断言弹文（frmVirtualStartup: Task asserted …/Unknown exception）+ 屏幕长时间纹丝不动 = 死帧，别再调输入姿势。
2. **恢复集耗尽后的有效重建路线 = 干净克隆**：克隆工位（复制时排除 RobotInit/SavePoints/恢复日志等消耗品/残集目录）+ 移除控制器状态镜像（CMOS/虚拟机器人状态文件，留证改名）→ 新工位上**虚拟机器人仿真器可重新生成**（进程起立，比原工位走得远得多）。若新工位的启动任务仍断言中止在网络层，则是环境层问题（安全软件网络注入等），非软件技巧可解。

## Fix

1. 死帧先判：断言弹文 + 屏幕静止 ⇒ 停止一切输入调试（省下大量句柄/坐标弯路），直接进入重建或等任务复活。
2. 重建配方（已实证走通到仿真器生成）：克隆工具复制工位（排除 RobotInit 等消耗品目录）→ 新工位删除控制器状态镜像（可逆留证）→ 引导 → 等「正在生成虚拟机器人仿真器」完成 → frvirtual 进程出现。
3. 终障若为网络层断言（如 PAL/传输层 assert）：换环境/安全软件白名单/人工在任务活着的窗口内介入，不硬磨自动化。

## Verification

死帧判据复现：对断言中止实例发任意输入无反应（界面逐字节不变），同通道对健康实例输入立即推进界面。克隆重建复现：原工位软修复穷尽后，克隆+删态引导可使仿真器进程重新生成（此前任何重启都未出现）。
