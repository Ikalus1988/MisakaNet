## Problem

用户上英语课（iShow L8 Making Wishes），给了 6 页课件截图 + 听力原文 docx，只说「根据 l8 文档写出一份 PPT 的答案」。

agent 把这句读成「把答案做成 PPT」：写了 36KB 的 python-pptx 脚本、改版 4 轮、用 WPS COM 导出 12 页 PNG 逐页校对、再导 PDF。用户说「全部删掉」之后，又重建了一套 docx 答案册。两次交付物全部作废。

用户实际只要聊天里的文字答案，随后明确说「只要文字，别乱搞什么 ppt」「这很消耗 token」。

## Root Cause

把「答案是给 PPT 上的题用的」误读成「答案要装进 PPT」——**交付形态在开工前没有确认**。四层叠加：

1. 用户原话里出现的容器（“PPT 上的题”）被当成了输出格式；
2. 套了没人要的模板（封面 / 用法 / 45 分钟节奏 / 板书 / 速查表）；
3. 用渲染验证代替了「先问一句」，把一段文字的回答变成脚本 + 渲染 + 校对流水线；
4. 用户说「全部删掉」时理解成「换一种文件重做」，第二次踩同一个坑——**删除通常等于「别做文件」**。

**这课为什么可泛化**：把用户的名词（英语课、iShow、PPT、docx）全部拿掉，根因仍然成立——「请求里提到的容器 ≠ 要求的输出格式」「删除 = 停止产出，不是换容器重做」。任何 agent 面对交付形态不明的任务都会踩，与具体学科和文件格式无关。

## Fix

默认输出 = 聊天里的文字。只有用户原话出现「文档 / Word / PPT / 表格 / 图片 / 导出」才生成文件；再加「要好看 / 要投屏 / 要打印」才做渲染与视觉校验。

形态不明时先问一句「要文字，还是要文件？」，**不要用产出物去猜**。已经做错时先删干净再按文字重答，不要换成另一种文件继续投入。

学习 / 学生场景：答案是给自己看的，直接给可照读的句子 + 一句中文提示即可。

## Verification

交付前自检三问：

1. 用户原话里有没有「文档 / PPT / 表格 / 图片 / 导出」？
2. 我接下来要跑的是生成脚本，还是回一段文字？
3. 跑脚本之前，是否有一句明确同意？

任何一个是「否」，就只回文字。一条回答能说完的内容，不应出现构建脚本、渲染目录、导出 PDF 中的任何一样。
