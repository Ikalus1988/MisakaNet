## Problem

批量导入/批量修改路径只写业务字段，没有触发派生状态（冗余状态列）重算，产生"字段已改、状态还是旧值"的自相矛盾数据，接口 200、页面无报错。

症状：台账系统里 `ship_weight`（发货重量）与 `item_status`（状态）并存，状态由规则算：有发货重量、无发货时间 → 「待发货」（超长件「待报检」）。运营用「批量修改 Excel」批量写发货重量后，60 行 `ship_weight` 有值、`ship_time` 空，但状态仍是「喷塑中 / 生产中」；对账发现 25 行与规则不符。

## Root Cause

单行编辑 `Update` 写完会调 `OrderStatusService.Refresh`（只有请求里真的改了状态下拉才跳过），称重录入写完会重算状态并调计价重算；**批量修改是第三条写入路径**，它按行拼 `UPDATE ... SET col=?`，写完只 `RowApplied++`，既没 Refresh 也没 Recalculate。派生字段同步靠调用方自觉，新通道漏了这一步，无任何编译期/运行期提示。

## Fix

批量执行循环里、`RowApplied` 自增前补两步：没改 `item_status` 就 `Refresh(db, qr)`；改了 `ship_weight/unit_weight/delivered_qty/order_qty/price_standard/thickness` 就 `Recalculate(itemId)`。历史脏数据按同一规则一次性回扫：筛 `ship_weight IS NOT NULL AND ship_time IS NULL AND item_status NOT IN (终态)`，逐行改状态并写审计，动库前先 `sqlite3.Connection.backup`（本次修正 25 行）。

## Verification

修后预览 1 行 → 执行 → 该行由 `喷塑中/空` 变 `待发货/5.5`；全库两条一致性查询（「有发货重量且无发货时间但状态不是待发货/待报检」「有发货时间但状态不是已发货」）都返回 0 行。

重跑一次批量改发货重量后读该行：状态变为待发货、不一致查询返回 0 行
