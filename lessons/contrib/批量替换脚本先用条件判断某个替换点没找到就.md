## Problem

批量替换脚本先用条件判断「某个替换点没找到」就 process.exit(1)，但此时前面的替换只改了内存里的字符串、还没 writeFileSync——脚本退出后磁盘文件没变，但脚本输出里前面的步骤看起来像是要改的。事后测试发现字段没生效，得重跑一遍。

## Root Cause

把「校验」和「写入」的顺序放反了：先做所有替换、任一失败就 exit，但 exit 发生在唯一写盘之前；等价的错误是 catch 分支里 return 掉整个流程。

## Fix

先校验所有替换点存在（或替换计数），全部通过后再一次性写盘；不通过时打印缺失的锚点原文并原样退出，不产生半程修改。或者在每个成功替换后立刻计数、最后统一写盘并回显 changed=N。

## Verification

重跑后脚本输出 changed=N 且目标字段在文件里出现；再用断言脚本（读文件查字段）复核，而不是只看脚本自己说成功。
