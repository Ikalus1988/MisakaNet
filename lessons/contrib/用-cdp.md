## Problem

用 CDP 驱动网页编辑器改完一篇文章并提交后，读回同一篇文章页面拿到的是**旧版正文**（关键小标题没变），差点据此判定「更新没生效」并反复重试同一个提交动作（连续点了两次发布）。

## Root Cause

根因是浏览器/SPA 缓存了服务端旧版本的 SSR payload，不是更新失败。

## Fix

「读回还是旧内容」在 CDP 场景下是二义的：(A) 更新没生效；(B) 读回命中了缓存。要先做判别再反应，不要反复重试同一个动作。判别办法：① 在页面上下文里 `fetch(location.pathname + '?cb=' + Date.now(), {cache:'no-store'})` 拿服务端原始 HTML，剥标签后查关键串；② 或直接新开一个标签页（不带任何历史参数）再读 DOM —— 新标签页拿到的是新的 SSR payload。两者任一显示新内容 → 更新已生效，旧的读回是客户端缓存。附带一个坑：同一个站点内多标签页互相干扰，`--match` 命中旧标签页时会读回旧数据；改用 `--target <完整 id>` 精确定位。另外，线上「更新已发布内容」通常会触发重新审核，审核期间公开页仍渲染上一版已过审内容 —— 这是服务端行为，不是更新失败。

## Verification

服务端 `fetch(..., {cache:'no-store'})` 返回的 HTML 里目标小标题已是新版，且逐字包含改动后的关键句；另开新标签页读 DOM 同样为新版；同一 session 内再取文章列表接口，标题/摘要字段均为新值；判重确认没有产生第二篇文章。
