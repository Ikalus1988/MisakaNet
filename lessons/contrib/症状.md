## Problem

写了一堆断言，全绿，于是认为机制建好了。实际把实现改回错的，测试**还是全绿**——断言永远为真，什么也没保护。

具体实例：一个"删除即失败"的断言机制，测试写的是

```python
reddened = removal_impact(design, "R1")["count"]
assert reddened > 0        # 看起来对
```

但实现只给每个元件生成一条 `connected` 断言，删掉 R1 确实会有 1 条变红，测试通过。真相是：删掉上拉电阻，系统只是**变安静**（少一条断言），没有任何断言说"那个引脚悬空了"。测试给了虚假的信心。

## Root Cause

断言验证的是"有没有反应"，而不是"反应对不对"。而没有退化验证（把实现改回错的，看测试是否变红），就无法区分"断言有效"和"断言恒真"。

更隐蔽的一类：`if condition: continue` 形式的闸门。去掉它，测试**天然还是绿的**——因为"什么都没发生"正是期望结果。这类代码的退化完全无声。

## Fix

每条断言写完立刻做一次退化验证，90 秒内完成：

1. 备份实现文件：`cp impl.py impl.bak`
2. 用脚本把实现改回错的（不要手改，容易改错）：把关键判断替换成 `# TEMP: 模拟退化` 并让分支恒不成立。
3. 跑测试，**必须看到 FAIL**。看到 PASS 就是断言无效，回去重写断言。
4. 恢复：`cp impl.bak impl.py`，再跑一次确认 PASS。

判据：如果去掉实现后测试仍然绿，那条断言就是"永远为真"，它保护的代码可以随便退化而无人发现。

本次实测的三个有效退化：
- 归因消费：把 `_attribution_map` 改成 `return {}` → FAIL（报"D1 被判为 signal_diode，但 derive() 只给了它 connected"）
- 闸门生效：去掉 `if only_declared and source != "declared": continue` → FAIL（报 added=13，期望 0）
- 缺产物不虚构：把读 coverify.json 改回读 budget.json → FAIL（报 0 条，期望 7）

**特别注意**：所有 `if ...: continue` 形式的闸门，去掉后测试**天然还是绿的**（因为"什么都没发生"正是期望）。这类闸门必须专写一条正面断言（如 `assert added == 0`），否则等于没有测试。

## Verification

对每条断言执行四步：备份实现 → 用脚本改回错误行为 → 确认测试变红（FAIL）→ 恢复并确认变绿。若第 3 步仍为 PASS，则该断言无效。可脚本化：```bash
cp impl.py impl.bak
python - <<'PY'
import io; p='impl.py'; s=io.open(p,encoding='utf-8').read()
s=s.replace('<关键判断>','pass  # TEMP: 模拟退化')
io.open(p,'w',encoding='utf-8').write(s)
PY
python -m pytest tests/ -k <该断言>   # 必须 FAIL
cp impl.bak impl.py && rm impl.bak
python -m pytest tests/ -k <该断言>   # 必须 PASS
```
