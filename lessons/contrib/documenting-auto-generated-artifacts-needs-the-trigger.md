## Problem

写工作流文档时，对某类自动产出的报告文件只写了一句「X 是自动生成的，每份备份都有」，没有写**由什么动作触发生成**。读者看完文档仍然要问「那我怎么导出它」——因为文档没有告诉他该做什么动作。

报料者给出的错误原文：

> 文档写「irdg_report.dg 自动生成、每份备份都有」，用户仍问「如何导出」，因为没写触发时机

代价是实打实的：报料者为弄清「怎么导出」排查了 15 条可能的导出路径。

更要紧的是，触发机制一旦查清，**整个操作方案会反转**：

- 文档给人的暗示：需要某个「导出」动作才能拿到该文件
- 实际机制：**做一次备份/存档就会自动生成并随备份带走**，无需任何额外导出

如果只写「自动生成」而不写触发时机，读者会以为要找导出入口，甚至去做无用功。

## Root Cause

把「产物的存在方式」当成「产物的获取方式」来写。二者不是一回事：

- **存在方式**：自动生成 / 手动导出 / 内嵌于备份
- **获取方式**：读者需要执行的**具体动作**

自动产出类文件的获取方式完全取决于**触发时机**（哪个动作、在哪个时刻、落到哪个目录）。不写触发，读者无法推断该做什么。

判据很硬（报料者给的）：如果文档里某文件只写了「自动生成」，读者看完仍要问「怎么拿」，就说明触发缺失。

报料者未给出：该软件的具体名称/版本，以及「备份/存档」这一步的官方命令或菜单名，需复现确认。

## Solution

描述自动产出物时，必须同时写三件事，缺一不可：

| 项 | 要写什么 | 本例中的答案 |
|---|---|---|
| **触发** | 哪个动作会生成它 | 做备份 / 存档 |
| **落点** | 生成到哪个目录 | 存档目录（**不在运行时目录**） |
| **批量推论** | 规模化时该怎么办 | N 份备份本来就都带，直接收集 |

**怎么验证触发**：对比产物与运行时目录的文件时间戳。

- 产物只出现在存档/备份目录、时间戳与存档瞬间一致、运行时目录没有 → 触发是「存档/备份」
- 运行时目录也有、时间戳持续更新 → 触发是「运行时周期性」

这条判据不需要读厂商文档，看文件时间分布即可断定。

**推论**：自动产出物往往让「导出 N 份」变成「收集 N 份已有备份」，批量成本可能从 O(N 次操作) 降到 O(1 次扫描)。写文档时点明这点，读者的方案会完全不同。

## Verification

- 文档中每个自动产出物都能回答：「要执行什么动作才能拿到它？」若答案是「做备份」，须明写；若读者仍需问，判为触发缺失。
- 批量场景须能推出「是否需要逐台操作」。
- 交叉核对：文档里写的触发时机，应与产物时间戳分布一致（仅出现在存档目录 = 触发是存档）。
- 失败基准（报料者实测）：只写「自动生成、每份备份都有」时，读者的下一个问题必然是「怎么导出」——出现这个问题就是验收失败。
