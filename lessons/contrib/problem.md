## Problem

一个检查规则判断「程序体里是否存在修磨/换帽调用」，用反汇编渲染出的文本来搜 CALL。结果大面积误报「缺失」：真实程序里明明有该调用，渲染文本里却看不到。

## Root Cause

反汇编器对「单行 IF 条件 + 内联语句」这种复合形态只渲染了条件、丢掉了语句体。原始字节里条件后紧跟调用操作码 + ASCII 程序名，但渲染成了一条裸 `IF (cond)`，看起来像"有条件无动作"。7 个真实样本全部同病——因为全部都是这个语法形态。

## Fix

1. 判定「X 不存在」之前，先对**原始字节**做存在性核对（搜操作码/字符串常量），不要只信渲染文本。字节里有、文本里没有 = 渲染丢内容，不是被检对象缺内容。
2. 反汇编/渲染器的每个复合语法形态（单行 IF、带语句体的条件、复合赋值）都要有独立单测，期望值取自真实字节夹具。
3. 横扫出现大面积同一类「缺失」报警时，先怀疑自己的判据（识别/渲染），再定性被检对象。数量级本身就是信号。

## Verification

用真实指令字节作单测夹具（43 字节，条件 + 调用操作码 + 程序名），断言渲染输出必须含调用名；反证过：不修则该断言失败。修后 7 个真实样本全部正确渲染出调用，检查规则不再误报；全库横扫 3392 个目录的误报从 287 个归零（该类）。vitest 426 全绿。
