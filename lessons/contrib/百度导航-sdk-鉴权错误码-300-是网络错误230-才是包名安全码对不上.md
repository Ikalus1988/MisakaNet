## Problem

真机跑百度导航 SDK，日志里连着出现两个非 0 值：

```
地图授权状态 = -300
地图网络状态 = 2（网络连接错误）
...
地图授权状态 = 230
地图网络状态 = 0（正常）
```

第一版把两个都标成「ak 校验没过」，排查方向被带偏一轮。

## Root Cause

这是**两件不同的事**，别混成一个：

```
E_PERMISSIONCHECK_CONNECT_ERROR = -300   // 链接服务器错误 ← 网络问题
E_PERMISSIONCHECK_KEY_ERROR     = 101    // ak 不存在
E_PERMISSIONCHECK_MCODE_ERROR   = 102    // Mcode 签名不正确
E_PERMISSIONCHECK_UID_KEY_ERROR = 200    // APP 不存在，AK 有误
```

`230` 不在本地枚举里，在百度 webapi 附录：Mobile 类型（Android/iOS）的请求要做安全码校验；安全码 = APP 签名 SHA1 + ";" + **包名**，不带或带不一致都返回 230。iOS 没有 SHA1，所以 **iOS 的安全码就是 Bundle ID**，必须和手机上实际包名逐字符一致。

踩法：SideStore 会给包名加后缀，控制台填 `cn.yqx.baiduprobe`、实际装的是 `cn.yqx.baiduprobe.PGV6836FJR` → 230。

## Fix

1. 控制台「修改」→ Bundle ID 填**加了后缀的实际包名**；或 SideStore 安装页把后缀删掉重装，让两边都是干净 ID。
2. 查实际包名：`xcrun devicectl device info apps --device <UDID> | grep <关键词>`。

两条附带教训：**错误码要逐个映射，不要用「非 0 即失败」糊过去**；**不要凭旧截图断言第三方控制台的配置**（配置类结论必须现看现值）；`authorizeNaviAppKey = 1` 不代表能用，那只是本地格式检查，真正鉴权结果是 `onGetPermissionState:`。

## Verification

授权状态稳定为 0（`onGetPermissionState:` 回调）；把控制台 Bundle ID 改回不一致的值能复现 230，证明映射正确。
