## Problem

大型文档做章节重组（拆章/并章/改名、内容搬家）后，正文与表格里的交叉引用（「见第 N 章」「见『旧章节名』」「→ 4.1」）指向被拆散或改名的标题，全部悬空。实例：原章标题拆入两个收纳区后，全文 18 处引用该章名的「见 XXX」全部指空；另一交付对象残留 9 处旧编号引用（第 N 章/第 N 节<PATH>），编号体系已删。验收时核了结构、数值、零丢失，唯独漏了引用图，终扫才发现。

## Root Cause

重组清单按「内容搬家」编制，没把「引用也是内容」算进去：交叉引用的目标是标题文本/编号，内容搬走或标题一改，引用即失效；验收断言清单里也没有「引号内章节名必须命中最终大纲」这一条。双对象（文档+本地 md）各自演化时，引用风格还会分叉（编号式 vs 章节名式）。

## Fix

1. 重构前提取引用图：grep 所有「见<PATH>）」类引用，列清单与新大纲对照，纳入搬家清单。
2. 收尾固定断言：抽取全文「」内章节名与 N.N 编号形成引用词表，与最终 outline 标题词表求差集，**差集必须为空**（可脚本化）。
3. 修复二选一：批量改引用为新标题名；或引用量大时，在新位置放一条「旧名 → 新位置」别名注（1 次插入解决 N 处悬空，读者可检索到）。
4. 多对象交付（云文档 + 本地文件）对同一引用词表各跑一次断言，防止两对象引用风格分叉。

## Verification

对重组后文档跑「引用词表 − 标题词表」差集断言：差集为空 = pass；非空即悬空引用清单。回归判据：改名前 grep 引用计数 N，重组后逐条确认 N 处要么指向命中目标、要么被别名注覆盖。

抽取「」内章节名+N.N 编号成引用词表，与最终标题词表求差集：空=pass；非空列出即悬空清单。改名前后引用计数逐条对账亦可判。
