## Problem

GUI 自动化里「点击毫无反应」有三种截然不同的病因，混治会越修越糟：①**死会话**——后端/控制器断连后前端 DOM 照常渲染、截图 OCR 一切正常，但所有点击惰性（在残影上反复调坐标/重试是无用功）；②**开关语义**——目标是 toggle（菜单项/磁贴），幂等重试的第二击把第一击刚打开的东西关掉，表现为「明明该响应却不响应」；③**渲染时序**——下拉/浮层未画完就点，落空。

## Root Cause

「点击→验证→重试」范式默认动作是幂等的、目标是活的、渲染是即时的——三条在真实 GUI 里都可能不成立，且失败表象完全相同（无变化）。

## Fix

重试前先**判病因**：a) 死会话判据=点一个「必响应」探针元素（关闭钮/确定钮）2-3 次无任何变化 ⇒ 先重建会话（重启前端/重连），不要在残影上考古；b) toggle 元素**只点一次**，开合用状态探针（截图特征/白块/哈希）确认后再决定是否补击，补击前先探「是否已开」；c) 渲染时序=点击间留足渲染时间（实测下拉 0.7s 不够、1.5s 稳），或先验证目标已渲染（OCR 找到目标词）再点。

## Verification

三场景各复现一次：死会话下探针元素 2-3 击无变化→重建会话后一击即响应；toggle 场景连发两击不出现「开又关」（第二击被状态探针拦截）；慢渲染下拉在 1.5s 间奏下菜单项点击命中率 100%。
