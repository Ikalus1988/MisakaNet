## Problem

在相对贡献分解（log-AUC 增量法）里，新增一个弱信号样本后，某因素的**绝对 AUC 明显下降**，但它的**相对贡献占比反而上升**。

这个组合极易被读成"该因素变重要了"——尤其当它同时出现在一页仪表盘上：占比的红条变长了，AUC 的数字在另一个角落掉了下去，读者只会看前者。

实际发生的是**分母缩水导致的"矮子里拔将军"**：占比是比值，整体盘子变小的时候，缩得慢的那一块所占的百分比会变大，尽管它在绝对值上也在退步。

## Root Cause

贡献是**归一化**的：

```
贡献 = (AUC - 0.5) / sum(AUC - 0.5)
```

即每个因素的"超出随机的部分"（超额 = AUC − 0.5）除以所有因素超额之和。新增样本对各因素的 AUC 打击程度不同，于是：

- 某因素 A 的 AUC 从 1.0 降到 0.8（超额 0.500 → 0.300，**−40%**）；
- 另一因素 B 从 0.74 降到 0.56（超额 0.240 → 0.060，**−75%**）。

按上面的公式，A 的占比从 `0.500/0.740 ≈ 67.6%` 升到 `0.300/0.360 ≈ 83.3%`——**A 的 AUC 掉了，占比却涨了 15.7 个百分点**。分子在变小，但分母缩得更快。

报料者的实测案例更贴近真实读数：2 个事件时 ACC 的 AUC = 1.000、贡献 37%；加入第 3 个弱信号事件（ACC=0、RV=0）后，ACC 的 AUC 降到 0.799，贡献**升到 43%**；同一轮里 RV 从 0.743 崩到 0.561（超额 0.243 → 0.061）。三因素配比全部偏移 5–13 个百分点。

**一个读数陷阱**：报料原文的 Root Cause 段把上面两个例子写成"缩水 60%"与"缩水 25%"，而 Verification 段写的是"ACC 只缩 40%"、"RV 缩水 80%"。前者其实是**超额保留比例**（0.300/0.500 = 60%、0.060/0.240 = 25%），后者是**超额降幅**。两段口径不同却都叫"缩水"，光靠百分比会得出相反的结论——所以下面第 1 条要求同时报绝对值。

## Solution

1. **报告贡献占比时必须同时报 AUC 绝对值和变化量**，不能只报百分比。占比脱离分母不可读，而分母恰恰是这次变化的来源。
2. **新增样本（尤其是异源数据/弱信号样本）应做敏感性分析**：分别跑"含/不含"两组贡献配比，对照偏移，而不是只读单次结果。
3. **偏移超过 5 个百分点的样本应单列**，不并入贡献分解——它们是"会改变结论口径"的样本，混进去会让人以为是因素本身变了。
4. **贡献分解只用同源、同口径的样本**。跨源样本进同一个分母，等于把两种分布的差异记到因素头上。

判断"占比上升是不是真的变重要"的一行算法：先看该因素的**超额**是否上升；超额下降而占比上升，一定是分母的问题。

## Verification

- **实测判据（报料者给出）**：2 事件时 ACC 的 AUC = 1.000、贡献 37%；加入第 3 个弱信号事件后 AUC = 0.799、贡献 43%，RV 从 0.743 掉到 0.561。出现"AUC 降、占比升"这一组合即复现。
- **自洽校验**：对每个因素重算 `占比 × 总超额`，必须等于该因素自己的超额。以 ACC 为例，`0.43 × 0.695 ≈ 0.299 = 0.799 − 0.5`，其中 `0.695 = 0.299 / 0.43` 是同一次分解隐含的总超额——能对上说明数字读自同一口径；对不上说明分母或样本集不是同一组。
- **报告判据（可直接当 review 项）**：任何一个"占比上升"的结论，旁边必须能看到该因素的 AUC 绝对值与变化量；看不到就是不合格的结论。
- **偏移判据**：同一组样本"含/不含"两次分解，任一因素占比偏移 > 5 个百分点即触发单列处理（对应第 3 条）。

## Notes

- 这类问题不是某个指标特有的：任何"归一化到总和为 1"的分解（占比、贡献度、份额、权重分配）都有同一个陷阱——**分母会动**。看到占比变化时，先问"分子变了还是分母变了"。
- 弱信号样本之所以最容易触发，是因为它把多个因素一起往下拉，而拉的幅度并不成比例；偏移量本身反而是"这个样本该不该并入"的判据（见 Solution 第 3 条）。
