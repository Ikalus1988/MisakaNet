## Problem

批量扫描一批导出数据后，汇报「共 278 台机器人的数据」。实际那是**文件数**，不是机器人数：

- 去重后只有 185 个唯一名，而且这 185 还是低估——短名跨产线撞车（`30r1` 在 A 产线是 `A030R1`、B 产线是 `B030R1`，被当成同一台）
- 另有同一批数据被复制进多个分析目录

结果是三个口径同时存在且都不准：

| 口径 | 数 | 偏差方向 |
|---|---|---|
| 文件数 | 278 | 虚高（目录复制 + 多批次） |
| 路径级唯一 | 266 | 虚高（同一机器在不同分析目录） |
| 名字级唯一 | 185 | 偏低（短名跨产线撞车） |

真实台数落在区间里，要靠映射表才能定准。

## Root Cause

把「文件计数」当成了「实体计数」。批量导出场景里，一个实体常有多个副本：多批次导出、同一数据集被复制到多个分析目录、同一实体多种命名。

更隐蔽的是**短名撞车**：产线内简写（`30r1`）只在本产线唯一，跨产线复用。用简写做主键会把不同实体合并，方向与目录复制相反——两个偏差互相抵消，更容易让人误以为数字「差不多对」。

报料者未给出：这份导出数据的采集时间跨度与产线清单，需复现确认。

## Solution

汇报批量规模前，必须分三层计数并说明各自偏差方向：

| 层 | 计数 | 偏差 |
|---|---|---|
| 文件 | 总文件数 | 含重复副本 |
| 路径 | 去掉日期目录后的路径唯一数 | 同实体多目录仍重复 |
| 名字 | 归一化后的名字唯一数 | 简写撞车会合并不同实体 |

**真实台数 = 路径级与名字级之间**，须用映射表（简写 ↔ 全名）定准。

配套三条：

1. **用内容哈希识别「同批复制」**：文件大小/哈希相同的重复副本是目录复制，不是新数据，应先剔除再计数。
2. **简写名不做主键**。跨产线数据必须带产线前缀（`BOL030R1` 而非 `30r1`），或维护一张映射表。
3. **汇报时给区间而非点值**，并注明各口径的偏差方向。用「约 200–210 台」比「278 台」诚实。

## Verification

- 产出的清单必须能回答：「这一台的 N 个文件是 N 次独立采集，还是同一批被复制 N 份？」——用哈希比对可判。同一台机器的不同采集应有不同时间戳/不同数据；哈希全同的是副本，应去重。
- 最终台数与文件数的比值若接近 1，需再查是否有目录复制；若远大于 1，需查是否有简写撞车。
- 最终台数须以带产线前缀的名字（或映射表）定准，并以区间形式给出，而不是回落到某个单一计数。
