## Problem

桌面应用（Tauri v1）「选择文件夹添加备份」，选到内容多的目录（几千个文件的整线备份库）软件直接卡死无响应。小目录完全正常。

## Root Cause

三层叠加，任何一层单独都不至于卡死：

1. **目录扫描无条目上限**：`scan_directory` 递归到底，大树能返回上万条 FileInfo，结果列表本身就把 IPC 撑大。
2. **一次性读全部文件 + IPC 序列化爆炸（主因）**：`read_backup_files` 把所有文件读进内存一次返回。Tauri v1 IPC 走 JSON，`Vec<u8>` 被编成 JSON 数字数组——每字节占 3~4 个字符。上千个几十 KB 的文件 = 数亿 JSON token，内存与字符串解析双双打爆，前端主线程卡在 IPC 反序列化上。
3. **前端单循环不让出线程**：读完之后逐个解压/反编译，全程没给渲染让过一次线程。

关键判据：小目录秒开、大目录必卡，且卡的是主线程（窗口变灰无响应）而不是转圈——这说明不是慢，是 IPC 载荷超了临界量。

## Fix

1. **后端护栏**：单次读上限（64 文件 / 96MB），超限返回**点名**的错误「请分批读取」；扫描条目上限（20000）截断。
2. **前端分批读**：32 个文件/批，批间 `setTimeout(0)` 让出线程；批次数大于阈值时给 loading 计数反馈。
3. **采集预算**：单文件大小上限 + 文件数上限 + 总字节上限，超限**明确提示**「请选更下层的目录」，不静默截断一半数据。

## Verification

- 单测：批大小 ≤ 后端护栏 / 96 文件 → 恰好 3 次 invoke / 进度回调 done,total 累计正确 / 结果收齐不丢不重 / 空列表不发 invoke
- 后端单测：超文件数拒 + 点名分批、超字节拒、预算内放行、扫描截断在上限
- 实测：3000 文件目录从「永久卡死」变为「几秒完成 + 有进度」
