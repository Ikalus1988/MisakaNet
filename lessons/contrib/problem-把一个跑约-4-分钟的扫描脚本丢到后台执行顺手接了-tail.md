## Problem

把一个跑约 4 分钟的扫描脚本丢到后台执行，顺手接了 `| tail` 想只看结尾：

```bash
long_sweep.mjs 2>&1 | tail -12   # run_in_background
```

结果：
1. **输出文件全程 0 字节**——`tail` 要等上游关闭才吐内容，中途没有任何进度
2. 更糟的是：它看起来「在跑」，实际进程早已退出。我去查 node 进程列表，发现**没有任何今天启动的进程**，才知道它根本没活
3. 同一时期另一次：`npm run gate 2>&1 | tee log` 后台跑，任务通知报 **exit code 0**，翻日志正文才发现是 `❌ release 层未通过`——**`tee` 的退出码盖住了 npm 的**，失败被洗成成功

两次都是「监控通道自己骗了自己」：一次把死的说成活的，一次把红的说成绿的。

## Root Cause

**管道里的每一段都会改写退出码与输出时序**，而后台任务的观察者只拿到管道末端：
- `cmd | tail -N`：`tail` 缓冲到 EOF 才输出 → 中途无进度；且 `tail` 的退出码是 0，与 `cmd` 无关
- `cmd | tee log`：`tee` 的退出码是 0 → 失败被掩盖（除非 `set -o pipefail`）
- 后台执行时没有 TTY，无法靠「感觉」发现异常

监控判据被**最弱的那一环**定义了，而不是被被测对象定义。

## Fix

1. **后台任务不要接管道**：直接 `cmd > log 2>&1`，让退出码与输出都来自被测对象
2. **要观察就用无缓冲过滤**：`grep --line-buffered` / `awk '{...; fflush()}'`；**别用 `tail`/`head` 做进度观察**
3. **管道必须 `set -o pipefail`**，让失败能传到最外层
4. **判据读日志正文，不读退出码**：`grep -q "层全绿"` 这类**结论行**比 `$?` 可靠
5. **静默 ≠ 正常**：输出长期为空、进程列表里找不到对应 PID，都要当成异常信号去查

## Verification

1. 故意让脚本失败 → 后台任务的通知**必须**显示非零退出码（验证 `pipefail` 生效）
2. 跑一个长任务 → 输出文件**必须**在运行中持续增长（验证无缓冲）
3. 杀掉进程模拟挂死 → 观察手段**必须**能发现（而不是显示 0 字节却以为在跑）

一句话判据：**后台任务的「成功」必须由被测对象的退出码 + 日志结论行共同证明，
不能由管道末端工具的退出码代替。**
