## Problem

需求是「故意骑错一个路口，路线应该几秒内更新」，但真机试骑判断不了——误报是偶发的，试十次可能一次都碰不到，凭感觉调参只会来回摇摆。

## Root Cause

偏航检测有一个**几何下限**：45° 转弯要骑到离路线 30m 才算偏航，按 15km/h 沿直行方向得骑 42m ≈ **10 秒**；垂直走错（90°）约 7 秒。这不是代码慢，是「必须骑出足够距离才能确认偏航」的物理约束。降阈值能更快，但开始误报。

## Fix

写离线仿真 `tools/nav-reroute-sim/`，用真实录制的三份 GPS（473 / 400 / 1226 点）跑参数网格，把「误报」和「触发时间」同时量出来：

| 参数 | 触发中位 | 路线偏 15m 时 |
|---|---|---|
| 35m/2点/无精度门限 | 10~19s | 不报 |
| **50 立即 / 30 两点 / 精度≤35** | **9~12s** | **不报（最大偏离 23.5m）** |
| 40 立即 / 20 两点 / 精度≤30 | 7~8s | ❌ 2/3 份数据误报 |
| 45 立即 / 25 两点 / 精度≤30 | 8~10s | 不报但只剩 1.5m 余量 |

试过但否掉的判据：航向判据（GPS 航向 vs 路线方位角 >75° 连续 3~5 秒）正常骑行 2~3 次/趟误报；进度停滞判据（4 秒内进度只涨位移 35%）在路线偏 8m 时误报 1~3 次；「只找剩余路段」与整条路线找最近点实测完全等价，不值得加状态。

体感上的「变快」主要来自另外两件事：旧路线不再被清空、SDK 轻量重算比完整算路快。

## Verification

```bash
swiftc BMSiOS/Geo/Geo.swift tools/nav-reroute-sim/main.swift -o <PATH> && <PATH>
```
预期：路线整体平移 15m 时误报 0；故意偏航触发时间中位 9~12 秒。
