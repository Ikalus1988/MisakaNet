## Problem

引导超时窗太短会伪造『间歇楔死』：慢启动被误判并误杀

虚拟工位引导在 300s 判定窗内未完成（services.txt 未重写），被判定为楔死并被清理重试，反复出现『时好时坏的间歇卡死』假象；清理动作本身又污染环境，故障面越修越大。

## Root Cause

引导耗时 5-7 分钟是该环境常态，而判定窗设为 240-300s——慢启动必然在窗内不完成，被误判 SERVICES-NOT-REWRITTEN=楔死；随后误杀正在引导的实例，再叠加清进程动作破坏共享宿主，制造出并不存在的『间歇故障』。

## Fix

判定窗放宽到 600s；超时后先探一次 HTTP 实答再谈断电/杀进程；把『慢引导』与『真卡死』分开处置：真卡死看崩溃签名（logfile 内存违例/模块 abort），慢引导只等不杀。

## Verification

对照判据：同一工位 600s 窗内 services.txt 重写即为慢引导成功（此前 300s 窗下同一动作失败）；真卡死判据 = 600s 仍不重写 + logfile 有崩溃签名 + HTTP 无实答。
