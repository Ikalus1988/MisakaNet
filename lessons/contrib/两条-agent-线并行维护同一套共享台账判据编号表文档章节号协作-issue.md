## Problem

两条 agent 线并行维护同一套共享台账（判据编号表、文档章节号、协作 issue 编号），各自从同一空位自增编号（两线都从 F20 起编、都用 §14 起的章节号、都开「3.2」小节）。同步时反复撞号：同一编号指两样东西（一词两义），跨文档引用悬空，合并冲突每轮复发（同一文件同一区域三度撞）。更隐蔽的是两线各自「定案」的结论互相推翻——因为对方的编号下没有我方语义，旧结论被静默继承。

## Root Cause

共享登记簿缺**命名空间约定**：并行写手在同一序列上自增是结构性冲突源，块级合并（择新/取超集）解决不了语义级撞号；且同步滞后下缺「结论改判」机制，翻案没有一等公民通道。

## Fix

1. **编号加线级命名空间后缀**：一线保数字系（F20-F98），另一线改带后缀系（F20g-F23g）——永不相撞；并行章节加前缀标记（如【G2线】§14）；
2. **合并纪律**：逐行择新取超集、分歧**并列写不互相覆盖**、疑似对方贴过的冲突标记当内容时以整文件超集判断；
3. **「改判」一等公民**：翻案必须显式标注（旧口径作废/以 X 为准），不允许新旧并存各表；
4. **单一互通面**：一份协调文件 + 领地表（文件归属）+ 环境拓扑（哪台机器有什么）+ 开工先读。

## Verification

约定落地后连续三轮合并零撞号；跨文档编号引用 grep 一次定位唯一行；两线各完成一例「改判」闭环（旧结论作废、新结论引用旧编号可回溯）。

约定后连续三轮合并零撞号；编号引用 grep 唯一命中；改判闭环可回溯（旧结论显式作废+新结论引用旧编号）
