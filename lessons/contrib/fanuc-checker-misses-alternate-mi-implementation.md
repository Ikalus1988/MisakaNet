# FANUC 备份检查 G-02 误报「缺展示位检测逻辑」：识别词表只认一种实现形态

## Problem

FANUC 备份检查工具的 **G-02「涂胶展示位检测」** 检查项，对一台实际已接入涂胶检测系统的机床报：

```text
缺展示位检测逻辑(INSPECT/SHOW/DI[443])
```

报告被当成「真实缺失」，一开始按报告结论准备转工艺补检测；后按「先查产物再下结论」的纪律去读原始备份，才发现并不是没有检测逻辑：子程序里
有 `CALL MI09_DSD(...)` 调用，也有 `DI[481]` 屏蔽信号 —— 只是这套 MI 包 / 信号命名不在检查项
认识的范围内，于是「已配置」被判成「缺失」。

备份文件路径、机床号与检查脚本路径报料者未给出，需复现确认。

## Root Cause

两件事叠在一起：

1. **识别词表只覆盖了 X 的部分实现形态。** G-02 的识别条件只认 `INSPECT` / `SHOW` / `DI[443]`
   这一套写法；现场用的是另一套 MI 包（`MI09_DSD`）与信号命名（`DI[481]`），于是「已配置」被
   判成「缺失」。同一个逻辑在 FANUC 上可以有多种合法实现形态，只认其中一种的检查，产出的是
   假阴性以外的假阳性——而它看起来比人工更权威。
2. **结论先于产物。** 报告读起来像结论，但没有人先去读原始备份。判据是：自动化报告里的每一条
   「缺失」都必须先在产物里核一遍，再决定要不要转工艺返工。

配套的第三个坑在横扫脚本上：**无报缺时提前 `return`、不写报告文件**，于是全绿之后磁盘上还留着
上一轮的报缺记录，汇总与报告自相矛盾。

## Solution

1. **先穷举 X 的全部合法实现形态**，出「形态 → 识别模式 → 出处」标准表。识别模式必须挂到标准
   文档 / 手册章节，不许拍脑袋写正则；表交领域方确认后才有资格改代码。
2. **领域方给出可选项边界后才动代码。** 本次领域规则是「该 MI 包是可选项，出现即认，不要求内含
   某个特定子指令」，据此把识别条件从「必须有检测调用」放宽为「出现该体系任一标识即认」。
3. **排除注释掉的调用。** 委托扫描必须走 `stripRemarks`：本次顺带抓到，注释里写 `!CALL XXX`
   就能骗过检查，等于把注释当成了实现。
4. **报告无条件落盘**：横扫脚本即使「无报缺」也要写报告文件，否则汇总与磁盘上的旧记录必然打架。

具体正则、脚本名与目录报料者未给出，需复现确认。

## Verification

1. 单测新增四类用例全绿：**该可选形态出现即认 / 注释里不认 / 完全没有仍报缺 / 旧口径回归**。
2. 全库同类横扫：原 `N-1` 通过 + `1` 报缺 → `N` 通过 + `0` 报缺，且报缺翻正的正是被误判那台，
   无新增误翻。
3. 全量回归横扫其他修复类别，100% 无破坏。
4. 报告文件的 `timestamp` / `g02fail` 字段与控制台汇总一致。
