## Problem

功能看起来没变，但某个已经修好的细节退回旧样子。实例：落地 v1.20 时 `LingboBridge.token` 又变回硬编码明文，而 main 上前一天已经改成 `BuiltinConfig` 注入了。

## Root Cause

多 AI / 多目录并行时，另一份目录里的同名文件是几小时前的快照。`cp` 过去等于把中间所有修复覆盖掉。Git 不会报冲突——这是在**工作区直接覆盖**，提交时看起来只是「一处改动」，review 时极易漏掉。

## Fix

1. 一律先 `git pull`，然后**在当前仓库的文件上改**，不要整文件覆盖；
2. 必须借外部版本时，先 `git diff` 对比，只取需要的那几行；
3. 提交前逐条看删掉的行：`git diff --cached -U0 | grep '^-'`，确认每一行都是自己有意删的；
4. 密钥类改动尤其要查：`git grep --cached -nE 'lb_[a-z0-9]{16,}'`。

根治办法是不要有多份副本目录——一个仓库只留一份代码。

## Verification

`git diff --cached -U0 | grep '^-'` 每一行都能解释来源；`git grep --cached -nE 'lb_[a-z0-9]{16,}'` 无命中；打出来的 ipa 里密钥仍来自注入配置。
