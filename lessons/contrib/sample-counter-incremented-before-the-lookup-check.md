# A sample counter incremented before the lookup check certified 61 tests that never ran

## Problem

A batch verifier checked one decision procedure across 61 samples. Its final line read:

```
tested=61 changed=0
```

Read at face value that is a strong result: 61 samples exercised, not one judgment flipped, so the
procedure is stable and there are no misses. The number was real. The execution was not.

Every sample first had to resolve an entry in a lookup table keyed by model identifier. When the
lookup missed, the sample was skipped. The counter sat **above** that check:

```python
tested += 1
spec = lookup(key)
if spec is None:
    continue
outcome = compute(spec, sample)
if outcome.changed:
    changed += 1
```

So the loop counted the sample, failed to find it, and moved on without ever running the
computation. Every one of the 61 samples took that path. The `0` was true — there were no flips
because there was nothing to flip.

## Root Cause

**The counter was measuring loop iterations, not evidence.** A skipped sample still executed
`tested += 1` on its way to `continue`, so the denominator included samples that produced no result.
The printed pair `(61, 0)` is generated by two different worlds:

- 61 samples executed and none flipped — the procedure is stable;
- 61 samples skipped and the computation never ran — nothing was tested.

The output cannot distinguish them, and because the second world reads exactly like the first, the
failure is a false negative shaped like a pass. The direction matters: a false red costs a round
trip; a false green ends the investigation.

**The conclusion was drawn from the numerator.** "0 changed" answers "how many flips did we see", not
"did we look". A zero means nothing without an independently known denominator. The loop did have
one — `len(samples)` — but nothing compared the printed count with it.

The same shape shows up whenever a stage can drop rows:

- a join silently loses unmatched rows, then `len(result)` is used as the sample count;
- `except Exception: continue` with no error counter, so crashed samples vanish from the total;
- a filter condition inverted, zero rows pass, and "0 failures" is printed;
- `all()` over an empty list, which is `True`.

## Solution

### Step 1: Count after the validity check, and count three different things

`attempted`, `matched`, and `executed` are not the same population. Print all three:

```python
attempted = matched = executed = flips = 0
for sample in samples:
    attempted += 1
    spec = lookup(sample.key)
    if spec is None:
        continue                     # attempted, but not matched
    matched += 1
    outcome = compute(spec, sample)
    executed += 1                    # a result actually exists
    if outcome.changed:
        flips += 1

print(f"attempted={attempted} matched={matched} executed={executed} flips={flips}")
```

Now the skip path is visible: `matched < attempted` names the samples the lookup dropped, before any
conclusion is possible.

### Step 2: Assert the denominator before reading the result

```python
assert attempted == len(samples), (attempted, len(samples))
assert matched == attempted, f"{attempted - matched} samples were skipped by the lookup"
assert executed == matched, "a matched sample produced no result"
```

Assert against the expected population, not against another counter that can drift the same way.
When the expected size comes from the same query that produced the samples, derive it from the
fixture or from the source list instead.

### Step 3: Make the conclusion conditional on execution

```python
if executed == 0:
    raise SystemExit("no sample executed — the run proves nothing about the procedure")
stable = executed == len(samples) and flips == 0
```

"0 flips" is only a result when `executed > 0`; a stable verdict additionally needs the full expected
population.

### Step 4: Add a probe sample that must flip

A probe is a sample the procedure is known to misjudge. If the probe does not flip, the harness is
broken, not the procedure. This catches the case where the counters look plausible but the
computation silently returns its default for every input.

## Verification

The same script, before and after, on the same 61 samples:

```
before:  tested=61  changed=0        # executed=0; every sample skipped at the lookup
after:   attempted=61 matched=61 executed=61 flips=7
```

The conclusion inverted: from "stable, no misses" to "7 judgments flip inside the reachable domain".
Two checkable criteria:

1. The printed counts satisfy `attempted == matched == executed == expected`; any mismatch is this
   bug, not a result.
2. `executed == 0` voids the run no matter what `flips` says.

The probe closes the loop: with the lookup repaired and a known-unstable sample in the set, `flips`
must be at least 1. A run where the probe stays quiet is a harness failure.
