# MisakaNet 零预算引流宣发完整方案 v1.0

## 一、方案概述

本方案针对 MisakaNet 产品阶段设计，全程零预算投入，聚焦历史验证有效的高转化渠道（飞书群 > Reddit），以「安全信赖 + 开发者互助」为核心逻辑，6个月周期实现获取 **100个真实留存用户** 的核心目标。

方案严格遵循「低成本验证优先、全链路数据埋点、障碍自动切换备选」的执行原则。

---

## 二、核心对齐信息

| 项目 | 内容 |
|------|------|
| **核心目标** | 6个月累计获取 **100个真实留存用户**（复访≥2次，认可产品核心价值） |
| **目标用户** | AI 入门人员（首次接触 Agent 工具、需要开箱即用的解决方案） |
| **差异化卖点** | ① 轻量（纯 Git 无额外服务）② 安全（纯文本 lessons，无代码注入风险）③ 兼容（跨设备、跨 Agent 框架） |
| **主攻渠道优先级** | 飞书群 > Reddit > X / 小红书 / Discord / 微信朋友圈 |
| **内容结构占比** | 安全信赖类 50% + 开发者互助类 30% + 产品说明类 20% |

## 三、分渠道执行策略

### 1. 核心渠道1：飞书群

**目标场景**：AI 工具用户群、开发者交流群、Agent 项目用户群

**执行动作**：
1. 每周在 3-5 个活跃飞书群发布 1 篇内容（安全信赖/开发者互助视角）
2. 主动回复群内的「踩坑求助」类问题，附上 MisakaNet 中对应的 lessons 链接
3. 邀请早期用户在群内分享真实使用体验

**埋点设计**：
- 给每个群的引流链接设置独立的 `?utm_source=feishu_群名称` 参数
- GitHub Pages 统计面板区分不同群的引流点击量
- 注册 Issue 标签区分来源：`source:feishu-xxx`

**转化路径**：
群内发言 → 群成员点击链接 → GitHub 主页阅读 README → 提交 Issue 注册节点 → 主动检索 lessons 解决问题 → 回头客验证

---

### 2. 核心渠道2：Reddit

**目标板块**：r/LocalLLaMA / r/MachineLearning / r/SelfHosted

**执行动作**：
1. 每两周发布 1 篇帖子（以「我遇到了 XX 问题，所以做了这个工具」的开发者第一视角）
2. 主动回复板块内的「Agent memory / cross-device sync」类问题
3. 回复时附上 MisakaNet 中对应 lessons 的具体内容，而非只丢链接

**埋点设计**：
- 每篇帖子的链接加入 UTM 参数：`?utm_source=reddit_post_编号`
- 评论区回复的链接加入 `?utm_source=reddit_comment`
- 注册 Issue 标签区分：`source:reddit`

**转化路径**：
Reddit 帖子/评论 → GitHub 主页阅读 README → 提交 Issue 注册节点 → 主动检索 lessons → 回头客验证

---

### 3. 核心渠道3：X / 小红书 / Discord / 朋友圈

**执行动作**：
1. X：每周发布 1-2 条短内容，聚焦 lessons 中有趣的踩坑案例
2. 小红书：以「AI 工具避坑指南」系列内容发布，适合入门用户

- 统一使用带参数短链：`?utm_source=平台名_内容编号`
- 注册 Issue 标签对应区分来源

**转化路径**：
平台内容 → GitHub 主页 → 注册节点 → 验证回头客

## 四、6个月执行时间线

### 阶段1：信任筑基期（第1-2个月）

**核心目标**：累计触达 500 个精准用户，获取 30 个早期种子用户

**关键动作**：
1. ✅ 完成所有渠道的链接埋点配置（UTM 参数统一规范）
2. ✅ 发布 10 篇渠道内容（安全信赖类 5 篇 + 开发者互助类 3 篇 + 产品说明类 2 篇）
3. ✅ 建立种子用户飞书群，配置入群欢迎语和问题响应机制
4. ✅ 准备好三大风险的标准应对文档（抄袭质疑 / 并发能力 / 代码注入）

**阶段验收**：
- 全渠道累计内容曝光 ≥ 2000 次
- 累计有效用户 ≥ 30 人（复访 ≥ 2 次）
- 种子社群人数 ≥ 20 人
- 埋点系统 100% 覆盖所有引流链接

---

### 阶段2：社群氛围建设期（第3-4个月）

**核心目标**：累计获取 65 个真实用户，形成稳定的用户互助社群氛围

**关键动作**：
1. 保持每周 3 篇内容的输出节奏，全渠道累计新增 20 篇内容
2. 启动「用户踩坑经验征集」活动，收集至少 10 个真实用户的使用体验
3. 完成所有已注册用户的 1 对 1 使用反馈收集
4. 每两周做一次渠道数据复盘，淘汰转化效果差的内容类型

**阶段验收**：
- 累计有效用户 ≥ 65 人
- 用户周留存率 ≥ 40%
- 评论区负面质疑占比 ≤ 10%
- 社群内用户自发互动占比 ≥ 30%

**零成本激励**：对贡献经验的用户提供「永久纪念节点编号」+ 优先体验新功能

---

### 阶段3：口碑自传播期（第5-6个月）

**核心目标**：达成 100 个真实留存用户的目标，实现用户口碑自传播

**关键动作**：
1. 整理 10 个真实用户案例，制作成内容在全渠道发布
2. 上线零成本邀请激励机制（邀请好友注册得「专属纪念编号」）
3. 复盘全渠道引流效果，将 80% 精力投入 ROI 最高的渠道
4. 整理用户常见问题，形成公开的 FAQ 文档

**阶段验收**：
- 累计有效用户 ≥ 100 人
- 用户月留存率 ≥ 30%
- 用户自传播带来的新用户占比 ≥ 20%
- 负面质疑占比 ≤ 5%

## 五、数据埋点机制

所有可追踪环节必须配置埋点，确保数据可量化：

### 1. 渠道来源埋点
- 每个渠道、每个场景、每个内容的引流链接都配置独立来源参数
- GitHub Pages 统计面板分渠道统计访问量、注册量、留存率
- 注册 Issue 自动带上 `source:xxx` 标签

### 2. 内容效果埋点
- 统计每篇内容的曝光量、互动量、点击量、转化量
- 识别高转化内容类型，优化后续内容生产方向
- 每周输出「内容转化排行榜」

### 3. 用户行为埋点
- 统计用户的使用频次（提交使用报告的频率）
- 统计 lessons 检索频率（哪些知识被反复使用）
- 统计用户留存时长，识别产品体验问题

### 4. 负面舆情埋点
- 定期收集所有渠道评论区的负面关键词（抄袭 / 并发 / 安全）
- 统计负面占比，对应调整内容策略
- 出现负面时 2 小时内响应

## 七、风险应对落地机制

针对三大核心风险，建立标准化的应对流程：

### 风险1：抄袭 evomap 质疑

**准备材料**：
- `docs/architecture_comparison.md` - MisakaNet 与 evomap 技术架构对比文档
- 核心差异点：MisakaNet 是纯 Git 分布式记忆，evomap 是中心化服务；MisakaNet 聚焦 lessons 共享，evomap 是完整 Agent 框架

**应对流程**：
1. 收到质疑后 **2小时内** 公开回应
2. 附上架构对比文档链接
3. 主动邀请提问者审核代码，验证差异
4. 强调「开源世界互相启发，但 MisakaNet 有独立的设计理念和实现路径」

---

### 风险2：Git 异步并发能力质疑

**准备材料**：
- `docs/git_async_design.md` - Git 异步设计的取舍与优势说明

**核心论点**：
- Agent 记忆共享不需要实时同步，分钟级延迟完全可接受
- Git 的分支机制天然支持并发写入冲突解决
- 异步设计 = 零基础设施成本 = 任何人都能自建网络
- 并发性能换来了极致的简单性和安全性

**应对流程**：
1. 第一时间公开说明设计取舍
2. 附上真实用户的使用场景案例（跨设备同步 lesson 不需要实时）
3. 透明化产品迭代路径：未来会考虑轻量级同步机制，但当前阶段简单性优先

---

### 风险3：代码注入安全风险

**准备材料**：
- `docs/security_model.md` - MisakaNet 安全模型说明

**核心论点**：
- lessons 是 **纯 Markdown 文本**，不包含任何可执行代码
- Agent 端只做读取和展示，不执行 lessons 中的任何内容
- 所有 PR 合并前都经过人工审核，防止恶意内容
- 用户可以自行 fork 仓库，完全掌控自己节点的知识来源

**应对流程**：
1. 收到质疑后立即附上安全模型文档
2. 强调「安全是 MisakaNet 的第一设计原则」
3. 主动邀请安全研究者做代码审计，公开审计结果
