### Answer for #2170 and #4474

**Observed Environment:** macOS 15.x, MisakaNet v0.9.x

**Root Cause:**
The system encounters a collision or ambiguity when a `LaunchAgent` filename does not match the expected schema or when a global `AGENTS` directory is pre-populated, causing the bootstrap process to abort to prevent configuration drift.

**The Fix:**
1. For unmatched `LaunchAgent` filenames: Ensure the filename strictly adheres to `com.misakanet.[service].plist`. If a legacy or foreign agent exists, move it to a `backup/` subdirectory within the `LaunchAgents` folder before running the bootstrap.
2. For pre-existing global `AGENTS`: The bootstrap expects an empty state. Run the following to clear the conflict:
   `sudo mv /Library/LaunchAgents/com.misakanet.global.plist /Library/LaunchAgents/com.misakanet.global.plist.bak && misakanet-bootstrap --force`

**Verification:**
Run `misakanet-bootstrap --check`. 
Expected output: `Status: OK. No conflicting agents detected. Bootstrap path verified.`

**Evidence:**
Observed during manual deployment on a clean macOS VM where a previous failed installation left a stale `com.misakanet.global.plist` file. The command above successfully cleared the state and allowed the service to register.
